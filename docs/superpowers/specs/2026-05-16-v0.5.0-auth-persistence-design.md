# v0.5.0 — Auth + Persistence (design)

> Status: design awaiting user review.
> Implementation plan to be generated next via `superpowers:writing-plans`.

---

## Goal

Sign-in with GitHub. Saved analyses. Repeat visits are fast. Signed-in users analyze targets using their *own* GitHub access token so they get a dedicated 5000-request/hour rate-limit budget instead of sharing the project's app-token quota. None of this changes the anonymous flow — the landing page still demos `/u/{username}` without an account.

This slice introduces the first stateful surface in the product. Everything before this was a stateless pipeline: GitHub → ingestion → scoring → narrative → page. v0.5.0 adds Postgres (Neon), opaque server-side sessions, and a small set of authenticated routes (`/me`, `/share/{slug}`, share-toggle). The deterministic scoring engine, the AI narrative layer, the SSE event shape, and the unauthenticated `/analyze` and `/narrative` endpoints are untouched.

## Non-goals (deferred)

- **Per-user rate limiting** — v0.10.0 (beta hardening). v0.5.0 adds the auth surface that rate limiting will hang off; the limiter itself is not in scope.
- **Background re-ingestion / freshness jobs** — v0.8.0 (caching). Saved analyses re-run only when the user clicks "Re-analyze"; no cron yet.
- **Shared/cross-instance session store** — Postgres is sufficient. Upstash session store is a v0.8.0 candidate when it lands for caching anyway.
- **Org-level sign-in or GitHub App** — out of scope. We use an OAuth App.
- **Email/password fallback** — out of scope. GitHub is the only identity provider.
- **OG card rendering for shared analyses** — v0.7.0 (GitHub Receipts™). v0.5.0 ships the share-slug URL; rich preview lands later.
- **PII export / account deletion UI** — schema supports it via CASCADE deletes, but no UI in v0.5.0.

## §1 — Architecture

```
Browser
  │
  │  GET /  (anonymous: unchanged)
  │  GET /u/{username}  (anonymous + authed: same view, signed-in users see a "Save" pill)
  │  GET /me  (authed: history grid)
  │  GET /share/{slug}  (anonymous: read-only public analysis)
  ▼
Next.js App Router (frontend/)
  │
  │  fetch(${backend}/auth/login)  ─► 302 to GitHub
  │  fetch(${backend}/me)  ─► JSON session payload
  │  fetch(${backend}/analyze/{user})  ─► JSON Report (+persists when authed)
  │  fetch(${backend}/narrative/{user})  ─► SSE (+persists when authed)
  ▼
FastAPI backend (backend/app/)
  │
  ├── /auth/{login,callback,logout}   ── new ── authlib + AES-GCM session store
  ├── /me, /me/analyses               ── new ── persistence/users + analyses
  ├── /analyses/{id}/share            ── new ── slug toggle
  ├── /share/{slug}                   ── new ── public read of shared analysis
  ├── /analyze/{user}                 ── unchanged shape; gains optional persistence
  └── /narrative/{user}               ── unchanged shape; gains optional persistence
  │
  ▼
SQLAlchemy 2.0 async + asyncpg
  │
  ▼
Neon Postgres (pooled, port 6543)
  └── users · sessions · analyses · analysis_runs · narratives
```

Three sequence flows worth pinning down:

**Sign-in:** Browser → `/auth/login` → set `si_oauth_state` cookie → 302 to GitHub → user consents → 302 back to `/auth/callback?code=…&state=…` → callback verifies state match, exchanges code for access token, fetches GitHub `/user`, upserts the `users` row, inserts a `sessions` row with the access token encrypted at rest, sets `si_session` cookie, 302 home.

**Authed analyze:** Browser sends `si_session` cookie with `GET /analyze/{username}`. FastAPI dependency resolves the session, decrypts the user's GitHub token in-memory, passes it to the existing `GitHubClient` (overriding the project token). After the report is built, we `upsert_analysis(user_id, target_login)` and `record_run(analysis_id, report)`. Anonymous request: no session, project token used as today, no DB write.

**Share slug visit:** Anonymous browser → `GET /share/{slug}` → backend resolves slug → returns the latest `analysis_run.report_json` with the owner's login attached → frontend renders `<ResultsView>` server-side. No session required, no narrative streaming (cached narrative from the run is rendered statically).

## §2 — OAuth flow

GitHub **OAuth App** (not GitHub App). Scopes baked in: `read:user`, `public_repo`. Never `repo`, never `admin:*`.

```
Browser                Backend                          GitHub
   |                      |                                |
   |  GET /auth/login     |                                |
   |--------------------->|                                |
   |                      | state = secrets.token_urlsafe(32)
   |                      | set cookie si_oauth_state (httpOnly,
   |                      |   Secure in prod, SameSite=Lax, 10-min TTL)
   |   302 to GitHub      |                                |
   |<---------------------|                                |
   |                      |                                |
   |  GET /login/oauth/authorize?client_id=…&scope=read:user%20public_repo
   |   &state=…&redirect_uri=https://app/auth/callback     |
   |------------------------------------------------------>|
   |   user consents                                       |
   |  302 → /auth/callback?code=…&state=…                  |
   |<------------------------------------------------------|
   |                      |                                |
   |  GET /auth/callback  |                                |
   |--------------------->|                                |
   |                      | assert cookie state == query state
   |                      | POST /login/oauth/access_token |
   |                      |------------------------------->|
   |                      |       access_token             |
   |                      |<-------------------------------|
   |                      | GET /user (token)              |
   |                      |------------------------------->|
   |                      |       user payload             |
   |                      |<-------------------------------|
   |                      | UPSERT users WHERE github_id=…
   |                      | nonce = secrets.token_bytes(12)
   |                      | ct    = AES-GCM(key, nonce, access_token)
   |                      | INSERT sessions (id, user_id, ct, nonce, expires_at)
   |                      | set cookie si_session  (httpOnly,
   |                      |   Secure in prod, SameSite=Lax, 30-day rolling)
   |                      | clear cookie si_oauth_state    |
   |   302 to /           |                                |
   |<---------------------|                                |
```

### Library choices

- **`authlib` 1.x** — `StarletteOAuth2App` with `name="github"` and standard GitHub endpoints. Smaller and less opinionated than `httpx-oauth`; first-class GitHub provider config.
- **`cryptography` (latest 44.x)** — AES-GCM via `cryptography.hazmat.primitives.ciphers.aead.AESGCM`. 32-byte key from env, fresh 12-byte nonce per row. No `python-jose`/`pyjwt` dependency — sessions are opaque, not JWTs.
- **`itsdangerous`** — *not* needed. We don't sign cookies (the session_id itself is the unguessable secret, and integrity isn't required because the server looks the id up directly).

### State token

10-minute httpOnly cookie `si_oauth_state` (`Secure` in prod, `SameSite=Lax`). Generated as `secrets.token_urlsafe(32)` (~256 bits of entropy, URL-safe). Mirrored in the GitHub query `state=` param. Callback compares constant-time (`secrets.compare_digest`) and 400s on mismatch.

### Failure paths

| Condition | Backend response | Frontend handling |
| --- | --- | --- |
| User clicks "Cancel" on GitHub | 302 to `/?auth=cancelled` | Inline toast on landing page, no error noise |
| `state` cookie missing or mismatched | 400 with generic body `{"error": "invalid_state"}` | Generic "Sign-in failed, try again" toast; do not echo the message |
| Code-for-token exchange fails | 502 | Same generic failure toast |
| GitHub `/user` returns 401 | 502 | Same generic failure toast |
| DB write fails | 500 | Same generic failure toast — log the traceback server-side |

### Logout

`POST /auth/logout` — idempotent. Reads the `si_session` cookie, deletes the matching row, clears the cookie via `response.delete_cookie("si_session")`, returns 204. Missing or invalid cookie is a no-op (still 204) so the UI doesn't have to branch on "are you signed in?" before calling logout.

## §3 — Database schema

Five tables. PostgreSQL types listed; SQLAlchemy 2.0 mapped classes live in `app/db/models.py`.

### `users`

```sql
CREATE TABLE users (
    id            BIGSERIAL PRIMARY KEY,
    github_id     BIGINT NOT NULL UNIQUE,
    github_login  TEXT   NOT NULL,
    name          TEXT,
    avatar_url    TEXT,
    created_at    TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at    TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
CREATE INDEX idx_users_github_login ON users(github_login);
```

`github_id` is the immutable numeric id and the upsert key. `github_login` is mutable (users can rename) but indexed because `/u/{login}` displays / share URLs reference it. Index is non-unique because GitHub allows reusing a login after a rename.

### `sessions`

```sql
CREATE TABLE sessions (
    id                  TEXT PRIMARY KEY,                           -- 43-char base64url (32B random)
    user_id             BIGINT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    access_token_ct     BYTEA NOT NULL,                             -- AES-GCM ciphertext
    access_token_nonce  BYTEA NOT NULL,                             -- 12 bytes
    expires_at          TIMESTAMPTZ NOT NULL,
    last_used_at        TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    created_at          TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
CREATE INDEX idx_sessions_user_id    ON sessions(user_id);
CREATE INDEX idx_sessions_expires_at ON sessions(expires_at);
```

The `id` is the cookie value — generated via `secrets.token_urlsafe(32)`. It is *not* an ORDER-able BIGSERIAL because we don't want session enumeration to be possible by guessing adjacent ids. AES-GCM `(ciphertext, nonce)` are stored as raw `BYTEA`. Cleanup of expired rows is a future cron (v0.8.0); the `idx_sessions_expires_at` index makes the eventual sweep cheap. `idx_sessions_user_id` supports "sign me out everywhere" (out of scope for v0.5.0, but the index costs almost nothing now).

### `analyses`

```sql
CREATE TABLE analyses (
    id              BIGSERIAL PRIMARY KEY,
    user_id         BIGINT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    target_login    TEXT NOT NULL,
    target_github_id BIGINT,                                         -- captured at first run, may be null briefly
    is_public       BOOLEAN NOT NULL DEFAULT FALSE,
    share_slug      TEXT UNIQUE,                                     -- 12-char base64url, populated only on opt-in
    latest_run_id   BIGINT,                                          -- denormalised, FK added after analysis_runs creation
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    UNIQUE (user_id, target_login)
);
CREATE INDEX idx_analyses_user_id       ON analyses(user_id);
CREATE INDEX idx_analyses_target_login  ON analyses(target_login);
```

The `(user_id, target_login)` uniqueness is the "save once, re-run many times" contract — re-analyzing octocat updates the existing row's `latest_run_id` instead of inserting a duplicate. `share_slug` is null until the user clicks "Share"; populated then is a 12-char `secrets.token_urlsafe(9)[:12]` (~72 bits of entropy) and an `is_public=true` flip. Toggling share off nulls both fields again — the slug is single-use; resharing generates a new slug, so an old shared URL stays revoked.

`latest_run_id` is a denormalised pointer that lets `/me/analyses` render without a per-row `JOIN ON (analysis_id = ?) ORDER BY ingestion_completed_at DESC LIMIT 1`. The FK to `analysis_runs` is added in a follow-up `ALTER TABLE` inside the same migration since the two tables reference each other.

### `analysis_runs`

```sql
CREATE TABLE analysis_runs (
    id                      BIGSERIAL PRIMARY KEY,
    analysis_id             BIGINT NOT NULL REFERENCES analyses(id) ON DELETE CASCADE,
    report_json             JSONB NOT NULL,
    total_score             SMALLINT NOT NULL,
    tier_name               TEXT NOT NULL,
    scores_hash             TEXT NOT NULL,
    ingestion_started_at    TIMESTAMPTZ NOT NULL,
    ingestion_completed_at  TIMESTAMPTZ NOT NULL,
    ingestion_latency_ms    INTEGER NOT NULL
);
CREATE INDEX idx_runs_analysis_id            ON analysis_runs(analysis_id);
CREATE INDEX idx_runs_analysis_completed     ON analysis_runs(analysis_id, ingestion_completed_at DESC);
```

`report_json` is the full Pydantic `Report.model_dump_json()` output as `JSONB`. We denormalise `total_score` and `tier_name` so `/me/analyses` can sort and filter without unpacking JSON. `scores_hash` mirrors the existing in-process narrative cache key — sha256 over the canonical Report JSON — so a future Upstash-backed shared narrative cache (v0.8.0) can use the same key without a second computation.

### `narratives`

```sql
CREATE TABLE narratives (
    id              BIGSERIAL PRIMARY KEY,
    analysis_run_id BIGINT NOT NULL REFERENCES analysis_runs(id) ON DELETE CASCADE,
    mode            TEXT NOT NULL CHECK (mode IN ('roast','mentor','recruiter','cto','career')),
    text            TEXT NOT NULL,
    model_name      TEXT,
    provider        TEXT NOT NULL,
    is_fallback     BOOLEAN NOT NULL DEFAULT FALSE,
    generated_at    TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    UNIQUE (analysis_run_id, mode)
);
CREATE INDEX idx_narratives_run_id ON narratives(analysis_run_id);
```

The CHECK constraint admits all five future modes up front — when v0.6.0 ships Recruiter/CTO/Career it does not need a schema migration. `provider` is `'openai'` for live calls, `'fallback'` for budget-exhausted runs. `model_name` is null only when `provider='fallback'`. Re-issuing a narrative for the same `(run, mode)` upserts.

### Cascade story

Deleting a user cascades to sessions → analyses → analysis_runs → narratives. Day-one GDPR-ish exit path. The owner's share slugs 404 immediately because the analysis row is gone.

## §4 — Backend module layout

```
backend/app/
├── auth/
│   ├── __init__.py
│   ├── oauth.py            # authlib StarletteOAuth2App config; build_authorize_url, exchange_code
│   ├── sessions.py         # create_session, get_session, delete_session, touch_last_used_at
│   ├── crypto.py           # AES-GCM encrypt/decrypt; load_key() fails fast on bad SESSION_TOKEN_ENC_KEY
│   └── dependencies.py     # FastAPI deps: optional_session, require_session, current_user
├── db/
│   ├── __init__.py
│   ├── engine.py           # async create_async_engine + async_sessionmaker; lifespan-managed
│   ├── models.py           # SQLAlchemy 2.0 mapped classes: User, Session, Analysis, AnalysisRun, Narrative
│   └── session.py          # get_db() FastAPI dependency yielding AsyncSession
├── persistence/
│   ├── __init__.py
│   ├── users.py            # upsert_user_from_github_payload(db, user_payload) -> User
│   ├── analyses.py         # upsert_analysis, record_run, set_share_slug, revoke_share_slug, list_for_user, get_by_slug
│   └── narratives.py       # save_narrative(db, run_id, mode, text, provider, model, is_fallback)
├── routers/
│   ├── auth.py             # /auth/login, /auth/callback, /auth/logout
│   ├── me.py               # GET /me, GET /me/analyses
│   ├── analyses.py         # POST /analyses/{id}/share, DELETE /analyses/{id}/share
│   ├── share.py            # GET /share/{slug}
│   └── narrative.py        # existing — extended to save on success
├── dependencies.py         # existing get_report_for_user gains an optional access_token override
├── main.py                 # mounts new routers, adds DB engine to FastAPI lifespan
└── migrations/             # alembic env
    ├── env.py              # async env using `db.engine`
    ├── script.py.mako
    └── versions/
        └── 20260516_0001_initial_v050_schema.py
```

### Notes on the layer split

- **`auth/` is the OAuth + session machinery.** It owns the cookie, the encryption key handling, and the GitHub OAuth dance. No DB-model imports leak out of `persistence/`; `auth/sessions.py` accepts an `AsyncSession` and calls into `persistence/`.
- **`db/` is pure data shape.** SQLAlchemy mapped classes only — no query logic, no orchestration. This keeps schema changes surgical.
- **`persistence/` is the query layer.** Every DB read/write goes through a named function here. Routers never touch SQLAlchemy directly. Makes the unit-test surface easy: mock the persistence module per router test.
- **`routers/` is HTTP.** Body parsing, status codes, response shaping. Each router file imports from `auth/` and `persistence/` only.
- **`dependencies.py` (existing)** grows one optional parameter — `access_token: str | None` — that, when set, overrides the project `GITHUB_TOKEN` for that request's `GitHubClient`. The `optional_session` dep resolves it.

## §5 — API surface

### Added

| Method | Path                          | Auth      | Returns                                |
| ------ | ----------------------------- | --------- | -------------------------------------- |
| GET    | `/auth/login`                 | none      | 302 → GitHub authorize                 |
| GET    | `/auth/callback`              | none      | 302 → `/` + sets `si_session`          |
| POST   | `/auth/logout`                | session   | 204                                    |
| GET    | `/me`                         | session   | `{user: {id, login, name, avatar_url}, counts: {analyses}}` |
| GET    | `/me/analyses?sort=…&page=…`  | session   | `{analyses: [...], page, total}` (20/page) |
| POST   | `/analyses/{id}/share`        | owner     | `{share_slug, share_url}`              |
| DELETE | `/analyses/{id}/share`        | owner     | 204                                    |
| GET    | `/share/{slug}`               | none      | `{report, owner: {login, avatar_url}, shared_at}` |

### Changed (existing endpoints)

| Method | Path                         | Change                                                                                |
| ------ | ---------------------------- | ------------------------------------------------------------------------------------- |
| GET    | `/analyze/{username}`        | Adds `optional_session` dep. When present, uses the user's decrypted token for ingestion and writes a run. Anonymous: identical to today. |
| GET    | `/narrative/{username}`      | Adds `optional_session` dep. When present, persists the assembled narrative on stream completion. SSE shape unchanged. |
| GET    | `/health`                    | Adds a `SELECT 1` DB ping (500ms timeout); reports `{status: "ok" \| "degraded", version, db: "up" \| "down"}`. |

### Error contract

- 401 only on session-required routes when the cookie is missing/invalid.
- 403 on `POST /analyses/{id}/share` when the analysis exists but `analysis.user_id != current_user.id`.
- 404 on `/share/{slug}` when the slug doesn't exist OR `is_public=false` (don't leak existence).
- All error bodies are `{"error": "<short_code>"}` — never a stack trace.

## §6 — Connection pooling & migrations

### Neon pooled connection

Single env var `DATABASE_URL` with the **pooled** host (`-pooler.<region>.aws.neon.tech`) on port `6543`. pgBouncer runs in transaction-pooling mode there, so two asyncpg quirks need handling:

1. `statement_cache_size=0` — asyncpg's default prepared-statement cache breaks against pgBouncer in transaction mode. Pass via `create_async_engine("postgresql+asyncpg://…", connect_args={"statement_cache_size": 0})`.
2. `prepared_statement_cache_size=0` (SQLAlchemy-side) — defence-in-depth; documented in the SQLAlchemy asyncpg dialect notes.

Pool config:
- `pool_size=5` — Vercel Functions are stateless and short-lived; 5 keeps per-instance concurrency healthy without pinning many idle connections.
- `max_overflow=5` — burst headroom.
- `pool_pre_ping=True` — survives pgBouncer-initiated disconnects on idle warm functions.
- `pool_recycle=1800` — recycle every 30 min as a belt-and-braces guard.

A separate `DATABASE_DIRECT_URL` (non-pooled, port 5432) is required by Alembic migrations because pgBouncer transaction mode cannot run multi-statement DDL transactions. Same Neon project, different host. Loaded only by `alembic/env.py`; the running app never touches it.

### Alembic config

`backend/alembic.ini` plus `backend/migrations/env.py` using SQLAlchemy 2.0 async patterns (the official template). One initial migration is generated and committed: `20260516_0001_initial_v050_schema.py`. Run via `uv run alembic upgrade head`. Downgrade tested in CI (the migration is `op.create_table` / `op.drop_table` symmetric, so reversibility is trivial).

The migration file is hand-edited, not autogenerated, so naming and ordering are deliberate. Models exist primarily for application code; the migration is the source of truth for what's in the DB.

### Lifespan wiring

```python
# app/main.py (sketch — full code in plan)
from contextlib import asynccontextmanager
from sqlalchemy import text
from app.db.engine import engine

@asynccontextmanager
async def lifespan(app: FastAPI):
    async with engine.connect() as conn:
        await conn.execute(text("SELECT 1"))   # fail fast if DB is unreachable at boot
    yield
    await engine.dispose()
```

No "create tables on startup" magic — schemas come from Alembic only.

## §7 — Frontend changes

The cinematic premium UI from v0.2.0/v0.3.0/v0.4.0 stays exactly as is. v0.5.0 adds auth chrome and one new route group.

### New routes

| Route              | Server-component? | Purpose                                                                |
| ------------------ | ----------------- | ---------------------------------------------------------------------- |
| `/me`              | yes               | Signed-in user's history grid (gated by session cookie)                |
| `/share/[slug]`    | yes               | Read-only public view of a shared analysis, no client fetch needed     |

### Header (`frontend/src/components/site-header.tsx`, new)

- Signed-out: small "Sign in with GitHub" pill in the top-right, anchor `href="${NEXT_PUBLIC_BACKEND_URL}/auth/login"`.
- Signed-in: avatar (or lucide `User` fallback) in the top-right opens a Base UI `Menu` with → "My analyses" (`/me`) and "Sign out" (`POST /auth/logout`, then `router.refresh()`).
- Auth state fetched via a `useSession()` hook backed by `GET /me`. Implementation: a module-scope `Promise<Session>` resolved on first call to `GET /me` (401 resolves to `null`), unwrapped via React 19 `use()`. Subsequent navigations reuse the cached promise; sign-in/sign-out invalidate by replacing the cached promise. Same shape as the data-fetching hooks Next 16 docs recommend for App Router.

### Results page additions (`/u/[username]`)

- Anonymous viewers: no chrome change. Bit-for-bit identical to today.
- Signed-in viewers: a small "Save" pill in the card footer. First click hits the existing `/analyze` (now persists). Subsequent visits show "Saved ✓" + a "Re-analyze" link. A "Share" button next to "Save" appears once saved. Click → `POST /analyses/{id}/share` → toast with copy-to-clipboard URL. The same button revokes when active.

### `/me` page

- Cinematic header — "Your engineering history" + `{counts.analyses}` count.
- Sortable grid (default: most recent first). Sort options: `recent`, `score_desc`, `score_asc` via `?sort=`.
- Each card is a compact `<HistoryCard>` (new component): target avatar + login, tier name + score, last-run-at relative, public/private badge. Click → `/u/[target_login]`. Reuses the v0.3.0/v0.4.0 typography and motion tokens.
- Empty state: on-voice copy ("Analyze your first developer →") + a `<SearchBar>` reuse, no skeleton.
- Loading state: 6 `<HistoryCard>` skeletons via the existing v0.4.0 Framer Motion stagger.

### `/share/[slug]` page

- Server component fetches `${backend}/share/{slug}` and renders `<ResultsView>` from the embedded `report_json`. No client-side fetch needed for first paint.
- A subtle "Shared by @{owner_login}" line under the tier badge — explicit attribution, no anonymous shares.
- The narrative card renders the saved narrative text statically (no SSE on shared views).
- `robots: { index: false, follow: false }` initially. We'll revisit when v0.7.0 receipts make shareable URLs a primary intent.

### `useSession()` hook (new)

```ts
// src/lib/auth.ts
export type Session =
  | { user: { id: number; login: string; name: string | null; avatar_url: string | null } }
  | null;

export function useSession(): { session: Session; loading: boolean };
export function useSignOut(): () => Promise<void>;
```

`useSession` uses React 19 `use()` against a module-scope cached promise resolved from `fetch(${backend}/me, { credentials: "include" })`. A 401 resolves to `null`. Cookies (`si_session`) handle all auth — no Authorization headers needed.

### Accessibility

- The header avatar menu uses Base UI `Menu` (keyboard nav + ARIA built-in).
- Save / Share / Sort controls wear `aria-pressed`, `aria-label` correctly.
- Toast for copied share URL uses `role="status"` so screen readers announce.

### Responsive design

Every new surface (`/me` grid, share button, sign-in pill, header menu) is verified at the standard mobile breakpoints (320 / 375 / 414 / 768) per the responsive-design feedback memo before the slice tags. No surface ships without explicit mobile QA.

## §9 — Testing strategy

### Backend

- **`tests/auth/test_crypto.py`** — round-trip encryption, AES-GCM nonce reuse detection, key length validation, bad-key fail-fast.

## §10 — Security considerations

| Surface | Threat | Mitigation |
| --- | --- | --- |
| OAuth callback | CSRF | httpOnly `si_oauth_state` cookie, 10-min TTL, `secrets.compare_digest` against query param |
| Session cookie theft | session hijack | httpOnly, Secure (prod), SameSite=Lax, 30-day rolling TTL, server-side row easily revocable |
| Stored GitHub tokens | DB dump leaks tokens | AES-GCM encryption at rest with key only on the running env, never in code or DB |
| `SESSION_TOKEN_ENC_KEY` rotation | breaking change | Key rotation invalidates all sessions by design; documented in `docs/DEPLOY.md` |
| Share slug enumeration | finding others' analyses | 72-bit slugs via `secrets.token_urlsafe`; `is_public=false` returns 404 (no distinction from "doesn't exist") |
| Open redirect in `/auth/callback` | phishing | We never honour a `redirect_to` parameter; callback hardcodes `302 /` |
| GitHub token scope creep | minimising blast radius | Hard-coded `read:user public_repo`; no admin or write scopes accepted |
| SQL injection | classic | Parameterised queries via SQLAlchemy 2.0; no raw f-string SQL |
| GDPR-ish account deletion | "delete my account" | CASCADE deletes wipe sessions/analyses/runs/narratives in one user delete; UI deferred but the schema supports it |
| `share_slug` revocation | old URL still works after revoke | Revoking nulls both `is_public` and `share_slug`; resharing generates a new slug |

## §12 — Known imprecisions & follow-ups

- **No session-id rotation on sign-in.** A fresh sign-in keeps the prior session's id if the cookie is replayed. Acceptable for v0.5.0 because the session row's `last_used_at` is updated, and the cookie itself is httpOnly. Rotate on logout (delete row → next sign-in generates a new id).
- **No CSRF tokens on state-changing routes.** `POST /analyses/{id}/share` and `POST /auth/logout` rely on SameSite=Lax cookies plus the fact that they're same-origin from our own frontend. If the share toggle gains a non-trivial blast radius, revisit with double-submit cookies. Documented here so v0.10.0 hardening doesn't have to rediscover it.
- **No per-user rate limiting.** Signed-in users get a dedicated GitHub quota (5000/hr) but unmetered Skill-Issue endpoints. v0.10.0 hardening adds the limiter.
- **No "sign out everywhere" UI.** Schema supports it; UI deferred.
- **No background re-ingestion.** Saved analyses re-run only when the user clicks "Re-analyze". v0.8.0 caching slice adds the cron path.
- **`DATABASE_DIRECT_URL` requirement on every env.** A small operational tax — both URLs must be configured per env. Documented in `docs/DEPLOY.md` as part of the v0.5.0 release.
- **Migration tests need a real Postgres.** CI gets a docker-compose Postgres service; local dev points at a Neon branch. The fixture sketched above is the contract.
