# v1.0.13 — Audit remediation and dependency refresh (design)

**Date:** 2026-09-30 · **Status:** approved by the operator (scope and decisions below) · **Slice type:** patch

## 1. Why

A whole-project audit on 2026-09-30 found production healthy but carrying latent defects, two critical upstream advisories, and a CI pipeline that had quietly stopped being able to merge anything.

Evidence came from reading the code end to end, empirical probes, and the live systems:

- **Production:** `skillissue.tech/_/backend/health` reports `1.0.12`, `db: up`, `cache: up`. The narrator streams a real roast in about 6s (not the fallback, not truncated). Vercel shows no runtime errors in the last 7 days, and the daily cron returns 200.
- **Sentry:** the backend has been clean since the 2026-08-19 Groq model retirement (0 errors in the last 5 weeks). The frontend's three unresolved issues are noise: the Microsoft Outlook link-scanner signature `Object Not Found Matching Id…MethodName:update` (33 events, 32 session replays consumed), an injected `app:///executors/200.js` script (16 events), and a single network blip. Frontend events carry no `release`.
- **Dependabot:** 17 open alerts, including **two critical Next.js RCEs** against `next@16.3.2` (fixed in 16.3.3). 12 PRs are open, and every one is red:
  - Frontend jobs fail on the audit gate (the Next.js criticals).
  - The uv PRs fail the `requirements.txt` drift guard, because Dependabot hand-edits a generated file.
  - The ESLint 10 and TypeScript 7 majors are blocked upstream.
- **Vercel build log:** Vercel installs the backend from `uv.lock`. It also warns that `"engines": {"node": ">=24"}` auto-upgrades on the next Node major, and every build installs `chromedriver` (pulled in by the unused `@axe-core/cli`).

### C. Correctness

| ID | Sev | Finding | Fix | Test |
| --- | --- | --- | --- | --- |
| C1 | medium | **Writes commit after the response is sent.** FastAPI 0.140 runs a yield dependency's teardown after the response by default (verified empirically with uvicorn: `/write` returned in 0.13s and an immediate read saw nothing committed). `get_db` commits in its teardown. Consequences: sign-in can land signed out (`/me` races the new session row); a first analysis may not be recognised as saved; deleted rows can reappear on `router.refresh()`; the share webhook fires before the slug commits; commit failures after a 2xx go unseen. | Add a `DbSession` alias, `Depends(get_db, scope="function")`, used at every site except the streaming narrative route. That route writes inside its generator, commits explicitly, and keeps a request-scoped session. | A structural test walks every route's dependency tree and fails on any non-streaming route with a request-scoped `get_db`. An ASGI-order test proves the commit precedes `http.response.start`. |
| C2 | medium | **Singleflight doesn't coalesce.** A waiter that acquires the lock after the holder releases is told `got=True` and re-ingests. N concurrent cold requests make N sequential GitHub ingests, contradicting the v1.0.5 CHANGELOG. | Double-checked read: after entering the lock, re-read the report cache before any live ingest. | Two concurrent `get_report_for_user` calls → exactly one ingest. |
| C3 | medium | **Cron rate-limit halt and outcome classes are dead code.** `_classify` matches `httpx.HTTPStatusError`, but `_live_ingest` converts every GitHub error to `HTTPException` first. A spent token keeps being hit for every row, and 404s and orgs are logged as `unexpected_error`. The existing tests only pass because they stub `_fetch_report` with the raw httpx error. `except BaseException` also swallows cancellation. | Classify through the real chain: `HTTPException` status, its `__cause__`, and the `service_busy` breaker. Catch `Exception`. | Drive `run_refresh_chunk` through the real `_fetch_report` with `_live_ingest` raising exactly what production raises. |
| C4 | medium | **Force refresh isn't fresh.** It deletes the report cache but still reads GitHub responses from the Layer-C cache (TTLs up to 1h). The v0.8.2 spec assumed that clearing the report cache made the pipeline "run cold". | `GitHubClient(read_cache=False)`: skip cache reads, keep write-through. Reached only through an internal `fresh=True` path that is not exposed as a query parameter. | Client-level test (no cache reads, still writes) plus a route test (the refresh ingests with `read_cache=False`). |
| C5 | medium | **"Share revoked" on failure.** The revoke path ignores the response status. A 401/403/500 still flips the UI to private while the link stays public. Share failures and history-delete failures are silent. | Check `r.ok` everywhere, show honest toasts, and leave state unchanged on failure | vitest: a 403 on DELETE keeps the shared state and shows the "still public" message |
| C6 | low | **Budget refund misses the common abort path.** A client disconnect usually lands as `CancelledError` while the generator awaits the LLM, not as `GeneratorExit`, so the slot is never refunded. The refund `await` also needs shielding under cancellation. | Handle both exceptions. Refund iff a slot was consumed (`meta.consumed_day` set). Wrap the refund in `anyio.CancelScope(shield=True)`. | Cancel the consuming task mid-stream → refund called once |
| C7 | low | **Force-refresh limiter fails open** on a Redis error or an unconfigured cache. The other limiters fail closed since v1.0.4 SI-01. | Extract the shared hourly-limit check from `make_rate_limiter`, including the in-process fallback, and use it in both | Redis error sentinel → in-process limiter enforces the cap |
| C8 | medium | **An Upstash outage stalls every cold analysis for 25s.** `RedisCache.set_nx` reports a Redis error as `False`, meaning "someone else holds the lock", so `singleflight` polls out its full 25s timeout before ingesting. The report cache is unreadable during the outage, so every analysis is cold. | `set_nx` returns `None` on a Redis error. `singleflight` treats `None` as "no lock service" and proceeds at once without waiting. | A failing FakeRedis → `singleflight` yields in well under a second |

## 4. Not in this slice

- **v1.0.14 — majors:** the list in §2, one package per commit, each proven locally first.
- **Python 3.13/3.14:** own slice, with a rollback plan.
- **CSP:** a report endpoint first. Browser-extension reports would draw on the Sentry error quota, so it needs a filtering decision. Enforcement comes after that.
- **CI drift check** between migrations and models (today's migration test only asserts that tables exist).
- `/health` returning 503 when degraded (today: 200 with `status: degraded`).
- **OAuth callback UX:** friendly redirects instead of raw 400/500 on a reused code or network error.
- **History pagination:** add an `id` tiebreaker.
- **Narrative `mode`:** validate before the ingest dependency runs.
- **Operator items:** the Sentry alert rule for the `narrative-fallback` fingerprint, source-map upload, and WAF/BotID/branch protection.
- **`vercel.ts`:** `entrypoint` points at directories, while `@vercel/config` documents `root`. There's no deprecation notice, and changing it safely needs a preview deploy.
