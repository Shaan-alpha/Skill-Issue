# v0.6.0 — GitHub Receipts™ Design Spec

**Status:** Designed. Implementation pending — TDD plan to follow under `docs/superpowers/plans/`.
**Date:** 2026-05-19.
**Author:** Claude (Opus 4.7) with Shaan.

---

## 1. Goal

Every analysis on Skill Issue produces a single canonical, shareable scorecard image suitable for LinkedIn, X, Discord, and rich-link previews. Pasting an analysis URL into any major social platform shows the card inline. A user can also visit a dedicated card preview page to download or copy the PNG directly.

This is **the** distribution mechanism for the product. The deterministic score is the product; the card is what travels.

## 2. Scope decisions (locked 2026-05-19)

| Decision | Choice | Why |
| --- | --- | --- |
| Card content | Tier + score + top 3 badges | Run-stable, no narrative dependency, instantly legible at thumbnail size |
| Render path | Next.js `@vercel/og` `ImageResponse` | Satori-based, fast on Fluid Compute, no headless-browser dependency |
| Theme | One canonical **dark** card | Matches site aesthetic; light variant deferred unless real demand surfaces |
| Share entry | Both: inline button + dedicated `/u/[username]/card` route | Inline = low friction, dedicated route = preview-before-share + power-user download |
| Narrative modes | Roast + Mentor only | Recruiter / CTO / Career formally dropped — moved to "Beyond v1.0" |

## 3. Surface area

### 3.1 New routes

| Route | Method | Visibility | Notes |
| --- | --- | --- | --- |
| `GET /u/[username]/og.png` | GET | Auth-aware | Owner-only for private analyses; anyone for analyses the user has publicly shared. 404 otherwise. |
| `GET /share/[slug]/og.png` | GET | Public | No auth required. 404 if slug unknown or revoked (identical 404 prevents enumeration). |
| `GET /u/[username]/card` | GET | Public page | Preview UI. Renders card preview + Copy PNG / Download PNG / Copy URL controls. |

### 3.2 Modified routes

| Route | Change |
| --- | --- |
| `GET /u/[username]` | Add OpenGraph + Twitter `summary_large_image` meta tags pointing at `/u/[username]/og.png`. |
| `GET /share/[slug]` | Add OpenGraph + Twitter meta tags pointing at `/share/[slug]/og.png`. |
| `save-share-controls.tsx` | Add "Share card" button (signed-in viewers on `/u/[username]`) — links to `/u/[username]/card`. |
| `share-attribution.tsx` | Add "Share card" button (any viewer on `/share/[slug]`) — links to `/u/[username]/card` keyed by the share owner's `target_login`. |

### 3.3 Components

| Component | Responsibility |
| --- | --- |
| `frontend/src/components/og-card.tsx` | Server component returning the JSX consumed by `ImageResponse`. Layout, typography, brand mark. No client interactivity. |
| `frontend/src/components/card-actions.tsx` | Client component for the preview page: Copy PNG (via `fetch` → `clipboard.write` Blob), Download PNG (`<a download>`), Copy URL (`navigator.clipboard.writeText`). |
| `frontend/src/app/u/[username]/card/page.tsx` | Server-rendered preview page. Fetches the report (same path as `/u/[username]`), embeds an `<img src="/u/[username]/og.png">` at correct aspect ratio + the action row + a "Back to report" link. |
| `frontend/src/app/u/[username]/og.png/route.ts` | `next/og` `ImageResponse` factory. Reads the report via the backend, hands it to `<OgCard>`, returns `ImageResponse(<OgCard report={...} />, { width: 1200, height: 630 })`. |
| `frontend/src/app/share/[slug]/og.png/route.ts` | Same as above, keyed by slug. |

```
│                                                                      │

│   │  47/100 within tier                           │  │     78      │ │

└──────────────────────────────────────────────────────────────────────┘
```

**Typography:** system stack via `next/og` font loader. One serif weight for the score number (Newsreader 700 or similar), one sans for everything else (Inter 500 / 600).
**Palette:** background `#0a0a0a` → `#111` very subtle vertical gradient. Text `#fafafa` primary, `#888` secondary. Score number tinted by tier band (Hobbyist amber → Principal indigo) — single accent colour, no rainbow.
**Brand mark:** "Skill Issue" wordmark top-right, `skill-issue-tau.vercel.app` micro-link bottom-right.
**Badges:** max 3, rendered as flat pills with the badge name only (no icons — satori SVG-icon support is finicky and avoiding them keeps render fast and deterministic).

## 5. Data flow

```
/u/octocat/og.png            (Next.js route handler, edge-eligible but runs on Node fn)
   ├─ session cookie → backend /me/analyses?target_login=octocat
   ├─ if owner OR public_share → fetch report
   ├─ else → 404
   └─ <OgCard report={...} />  →  ImageResponse(1200×630, PNG)

/share/<slug>/og.png         (Next.js route handler)
   ├─ backend /share/<slug>
   ├─ if 200 → <OgCard report={...} />  →  ImageResponse
   └─ if 404 → 404
```

Backend is unchanged. No new FastAPI endpoints. The card route consumes the existing report shape — the Report Pydantic model already exposes everything the card needs (`username`, `tier.name`, `tier.sub_rank`, `tier.band`, `tier.next_tier`, `tier.pts_to_next`, `badges[].name`, `total`).

## 6. Determinism + caching

- The card is a pure function of the Report. Two renders of the same `scores_hash` produce byte-identical PNGs. Snapshot test asserts this.
- `next/og` `ImageResponse` honours `Cache-Control` headers. Set `s-maxage=300, stale-while-revalidate=86400` on the route handlers. Vercel's edge cache handles the rest; we don't need Upstash for this slice (it lands in v0.7.0).
- Cache key is the URL itself — `/u/octocat/og.png` and `/share/abc123.../og.png` cache independently. If the underlying report is re-ingested and the score changes, the URL is the same but the cache eventually expires; we accept ≤5min staleness on the OG image for the simplicity win.

## 7. Performance budget

| Metric | Target |
| --- | --- |
| p95 PNG render time | ≤ 800ms (cold) / ≤ 50ms (warm via edge cache) |
| `/u/[username]/card` page TTI | ≤ 1.5s on 4G |
| PNG byte size | ≤ 80KB (satori + AVIF-fallback PNG) |

## 8. Testing strategy

- **Backend:** no changes; existing 142 tests stay green.
- **Frontend unit:**
  - `og-card.tsx` snapshot test — renders to JSX with three fixture reports (Hobbyist / Senior / Principal), assert structure.
  - Tier-band colour helper — pure function, fully unit-tested.
- **Frontend integration:**
  - Route handler test for `/u/[username]/og.png` — mock backend, assert `Content-Type: image/png`, assert non-trivial byte length, assert 404 on private-non-owner.
  - Route handler test for `/share/[slug]/og.png` — mock backend, 200 + 404 paths.
- **Visual:**
  - Generate a fixture PNG for each of the 3 tier samples and commit them under `frontend/tests/fixtures/og/` for byte-equality regression. (Generation script: `scripts/regen-og-fixtures.ts`.)
- **Real-world preview:**
  - Manual: paste live `/share/<slug>` URL into X, LinkedIn, Discord. Card must show inline.

## 9. Exit criteria (mirrors PLAN.md v0.6.0)

- [ ] `GET /u/{username}/og.png` returns a valid PNG in under 800ms p95 on Vercel for a warm analysis.
- [ ] `GET /share/{slug}/og.png` returns the same card for the shared analysis with no auth.
- [ ] `/u/{username}/card` renders the preview + 3 actions (Copy PNG, Download PNG, Copy URL) and looks correct at 320 / 375 / 414 / 768 / desktop widths.
- [ ] Pasting `https://skill-issue-tau.vercel.app/share/<slug>` into X and LinkedIn shows the card inline.
- [ ] Two renders of the same analysis yield byte-identical PNGs (snapshot test).
- [ ] `CHANGELOG.md` + `docs/PROGRESS_LOG.md` updated; version `0.6.0`.

## 10. Out of scope (explicit, do not silently expand)

- Light theme variant.
- "Full breakdown" multi-card variant (six bucket bars).
- Per-platform tailoring (separate dimensions for X vs LinkedIn).
- Animated / video cards.
- Backend Playwright fallback for the render.
- Analytics on share events (lands in v0.8.0 Observability).
- Rate limiting on the OG endpoint (lands in v0.9.0 Hardening).

## 11. Known imprecisions

- `clipboard.write(Blob)` for PNG copy requires HTTPS and a recent browser. We fall back to a download-only experience on Firefox <127 and Safari <16.4 — both feature-detected at runtime. No polyfill.
- The OG route reads the report by calling the backend, not the DB directly. One extra hop per render, but it keeps the OG layer framework-pure and consistent with the existing `/u/[username]` rendering path. Acceptable until v0.7.0 caching collapses the hops.
- `next/og` font loading happens on every cold start. Fonts are bundled in the route, not fetched. ~120KB of font data per route — acceptable.
