# v1.0.7 — Low-severity hardening + version-display fix — Design

> **Status:** draft 2026-07-25, awaiting user review before `writing-plans`.
> **Slice family:** v1.0.x post-launch hardening.
> **Origin:** the LOW/INFO tail of the 2026-07-24 audit + one operator-reported bug (the UI shows a stale version) + one bonus finding discovered during v1.0.4 (secrets leak into pytest output).

## 1. Goal

Clear the cheap, low-risk remainder of the audit and fix a real display bug: the frontend has shown **v1.0.3** through the v1.0.4–v1.0.6 releases because a third version constant (`APP_VERSION`) was never bumped. This slice fixes that (and prevents recurrence), plus seven small hardening items. No behavioral change beyond the fixes themselves.

## 3. Design per item

### VER — version display (the operator-reported bug)
Three version constants exist and drifted: `backend/app/settings.py::VERSION`, `frontend/package.json::version`, and `frontend/src/lib/site.ts::APP_VERSION` (the one the UI renders on the landing page and report). Bump `APP_VERSION` to `1.0.7`, and add a **vitest** that imports `../../package.json` (`resolveJsonModule` is already on) and asserts `APP_VERSION === pkg.version`, so a future ritual that forgets it fails CI loudly. The version ritual (Task: docs) will now bump all three.

### ENV — secret leakage into test output (bonus finding)
`Settings()`'s repr prints every field value; a pytest failure that reprs a `Settings` (e.g. a default-mismatch assert) dumps real secrets from a local `.env` into the terminal/CI log. Mark the secret fields with `Field(repr=False)`: `github_token`, `openai_api_key`, `github_oauth_client_secret`, `session_token_enc_key`, `database_url`, `database_direct_url`, `upstash_redis_rest_token`, `cron_secret`, `revalidate_secret`, `internal_proxy_secret`, `sentry_dsn`. Test: `repr(Settings(...))` contains none of a set secret's value.

### SI-34 — URL encoding
`u/[username]/page.tsx:42` builds `/analyze/${username}` raw while every sibling call site encodes it. Wrap: `encodeURIComponent(username)`. Backend regex already rejects malformed input; this is consistency/defense-in-depth. Test: the existing page test (or a small unit) confirms the encoded URL.

### SI-35 — README size cap
`get_repo_readme_text` and `get_profile_readme` base64-decode the whole `content` with no local bound (relies on GitHub's ~1MB cap). Add `content = content[:1_400_000]` before decode in both (insulates against an upstream change; ~1.4MB of base64 → ~1MB decoded). Test: an over-long `content` is truncated before decode (no huge allocation), normal READMEs unaffected.

### SI-36 — commit-message regex bound
`_commit_message_quality` / `_CONVENTIONAL_PREFIX` run on untrusted commit text. Truncate each message to a fixed max (e.g. 500 chars) before `splitlines()`/regex, and bound the scope group `\((?:[^)]{0,100})\)`. Test: a pathological long message is handled fast + correctly; existing quality scores unchanged for normal messages.

### SI-14 — credentialed CORS wildcard guard
Nothing stops an operator setting `CORS_ALLOW_ORIGINS=*` (with `allow_credentials=True`), which reflects the Origin + credentials — the classic hole. Add a boot-time guard (a pydantic `model_validator` on `Settings`, or an assert in `main.py` before adding the middleware) that raises if any `cors_allow_origins` entry is `*`. Test: `Settings(cors_allow_origins="*")` (or the guard fn) raises; a normal origin passes.

### SI-18 — cron response body trims ownership map
`refresh_saved_analyses` returns an `outcomes` array with `owner_user_id` + `target_login` per analysis — a who-analyzed-whom map that lands in Vercel/CDN logs. Return only aggregate counters (`processed`/`succeeded`/`skipped`/`rate_limited`/`deadline_reached`/`purged_sessions`); move per-analysis detail to a structured debug log (or drop `owner_user_id`/`target_login` from the response items). Test: the response body has no `owner_user_id`; counts still present.

### SI-33 — SSE terminal-error signal
`createNarrativeEventSource`'s `es.onerror` calls `onComplete()` (success) — a dropped stream shows as "finished". Distinguish: on `onerror` when `es.readyState === EventSource.CLOSED`, call `onError`; otherwise (transient/reconnecting) leave it. Since we `es.close()` on error, treat it as terminal → `onError`. Test: a simulated error invokes `onError`, not `onComplete`.
