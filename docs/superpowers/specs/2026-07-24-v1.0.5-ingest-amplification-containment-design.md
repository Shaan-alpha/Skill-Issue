# v1.0.5 — Ingest amplification containment — Design

> **Status:** draft 2026-07-24, awaiting user review before `writing-plans`.
> **Slice family:** v1.0.x post-launch hardening.
> **Origin:** the 2026-07-24 security audit, Workstream C — split out of v1.0.4 so the hottest code (GitHub client, ingest fan-out, narrative streaming, singleflight locks) gets its own review/verify cycle.
> **Scope decision (user, 2026-07-24):** ship the high-value **core** of each of the 5 findings; defer the 3 complex **extensions** to **v1.0.6**.

## 1. Goal

A single cold `/analyze` fans out ~100 GitHub calls on the shared anonymous token, with no per-analysis cap, no wall-clock deadline, uncapped `Retry-After` sleeps, a budget that leaks on client abort, an OG/card path that triggers unattributed ingests, and a singleflight lock that can stampede. This slice bounds each of those so a trickle of traffic can't exhaust the shared GitHub token, the worker pool, or the LLM budget. No user-facing feature change.

## 2. Scope

**In scope — the 5 cores:**

| ID | Core fix | Files |
| --- | --- | --- |
| SI-03 | Per-analysis **hard call cap** in `GitHubClient._request` | `github/client.py`, `dependencies.py`, `settings.py` |
| SI-06 | Cap `Retry-After`, HTTP-date-safe parse, handle `429`, **ingest wall-clock deadline** | `github/client.py`, `dependencies.py`, `settings.py` |
| SI-07 | **Budget refund on client abort** (kills abort-amplification) | `narrative/budget.py`, `routers/narrative.py` |
| SI-08 | Forward `x-client-ip` + `x-internal-secret` from the OG/card fetch (attribution) | `frontend/src/lib/og-card-data.ts`, the 3 OG/card routes |
| SI-09 | Raise lock TTL + **holder-checked delete** | `cache/keys.py`, `cache/client.py`, `cache/locks.py` |

**Out of scope — deferred to v1.0.6 (pre-registered in `PLAN.md`):**
- SI-03 **shared-token quota breaker** (read `X-RateLimit-Remaining`, persist to Redis, shed anon load) — needs cross-request quota state + an `is_shared_token` discriminator plumbed through `GitHubClient`.
- SI-07 **concurrent narrative stream coalescing** — SSE can't be trivially coalesced (the elected runner streams live; waiters can't re-read a mid-flight value); needs a streaming-aware singleflight + plumbing `RedisCache` into `NarrativeService`.
- SI-08 **store-gating** OG/card behind an already-stored analysis — a product-behavior change (OG previews for never-analyzed users would show a fallback).

**Rationale for the split:** the cores close the actual abuse (each analysis bounded, aborts don't drain budget, OG ingests attributed + subject to the anon limiter, locks don't stampede). The extensions are refinements with real complexity/product risk.

## 3. Grounding (from the 2026-07-24 ingest-surface map)

- **Choke point:** every REST/GraphQL call funnels through `GitHubClient._request` (client.py:74); exactly **one `GitHubClient` per analysis** (dependencies.py:149 `async with GitHubClient(...)`). A per-instance counter in `_request`, incremented on the **live** path (after the cache-hit early return at client.py:90), equals live-calls-per-analysis and is the natural cap point.
- **Worst-case fan-out ≈ 98 live calls** (Staff tier): base ingest ~56 (6 fixed + ≤20 root-contents + ≤20 languages + ≤10 commits) + Professional +30 (top10 × {license, workflows, readme}) + Senior +6 (review-depth + top5 contents) + Staff +6 (top5 commit-samples + contribution count). Per-repo fans are capped by `ROOT_CONTENT_LIMIT=20` / `top10` / `top5`, so fan-out scales with `min(non_fork_repos, cap)` — small accounts are 20–40.
- **SI-06 has three defects** at client.py:96–100: (1) unbounded `await asyncio.sleep(float(Retry-After))`; (2) `float()` raises `ValueError` on an RFC-7231 HTTP-date `Retry-After`; (3) a plain `429` bypasses the retry branch entirely (guard is `403`-only) so its `Retry-After` is ignored. No wall-clock deadline exists anywhere in `_request` or `_live_ingest`.
- **SI-07 abort:** budget consumed at service.py:72, cache written only at service.py:107; a mid-stream abort raises `GeneratorExit` (a `BaseException`, so `except Exception` at service.py:94 misses it) → cache skipped, budget never refunded, next same-key request is a fresh miss that re-charges.
- **SI-09:** `singleflight` release is an **unconditional** `cache.delete` (locks.py:67,80) — `holder_id` (locks.py:58) is generated but never checked — and `TTL_LOCK_SECONDS=30` (keys.py:36) can be shorter than a worst-case cold ingest, so a TTL-expired lock re-acquired by a second worker gets deleted by the first worker's `finally`, compounding duplicate ingests.
- **SI-08:** `fetchReportForUser` (og-card-data.ts:12–23) forwards **no** headers (`cache:"no-store"`), unlike the main proxy `getAnalysis` (page.tsx:32–45) which forwards `x-client-ip` + `x-internal-secret`. Reached by `opengraph-image.tsx:19`, `twitter-image.tsx` (re-export), and `card/page.tsx:26`. OG/twitter carry `s-maxage=300`; `card/page.tsx` has **no** CDN cache. Distinct usernames bypass the CDN cache → each cold-renders a live ingest.

## 4. Fix A — SI-03 per-analysis hard call cap

**`GitHubClient`** gains a `max_calls: int | None = None` constructor param (mirroring the existing `max_retries`) and a `self._live_calls = 0` instance counter.

In `_request`, **after** the cache-hit early return (so cached calls are free) and **before** the live-request loop:

```python
if self._max_calls is not None:
    self._live_calls += 1
    if self._live_calls > self._max_calls:
        raise GitHubCallCapExceeded(self._live_calls, self._max_calls)
```

New exception `GitHubCallCapExceeded(Exception)` in `github/client.py`.

**`dependencies.py`:** construct the client with the cap — `GitHubClient(token=access_token, cache=cache, max_calls=settings.gh_max_calls_per_analysis)` (dependencies.py:149). In `_live_ingest`, catch `GitHubCallCapExceeded` and raise `HTTPException(503, {"error": "analysis_too_large"})` (logged `analyze.call_cap_exceeded`, no username in the body). Default cap **150** — ~1.5× the ~98 legit worst case, so no real account trips it; only runaway/abuse does.

## 5. Fix B — SI-06 Retry-After cap + HTTP-date parse + 429 + ingest deadline

**In `_request` (client.py:96–100)**, replace the 403-only branch with a helper that also covers `429`, parses safely, and caps the sleep:

```python
def _retry_after_seconds(resp, *, ceiling: float) -> float:
    raw = resp.headers.get("Retry-After", "1")
    try:
        secs = float(raw)
    except ValueError:
        # RFC-7231 HTTP-date form.
        dt = parsedate_to_datetime(raw)  # email.utils; None/err -> default
        secs = max(0.0, (dt - datetime.now(UTC)).total_seconds()) if dt else 1.0
    return min(secs, ceiling)
```

Retry when `resp.status_code in (403, 429)` and the body/headers indicate a rate limit; sleep `_retry_after_seconds(resp, ceiling=settings.github_retry_after_ceiling_seconds)` (default **10.0s**).

**Ingest deadline:** wrap the ingest in `get_report_for_user` with `asyncio.wait_for(..., timeout=settings.analyze_ingest_deadline_seconds)` (default **45.0s** — comfortably above a legit cold ingest, well below Vercel's 300s function timeout). On `TimeoutError` → `HTTPException(503, {"error": "analysis_timeout"})`, logged `analyze.ingest_deadline`. Applies to the two `_live_ingest` call sites in `get_report_for_user` (inside the singleflight and the no-cache path); the cron path keeps its own separate `deadline_seconds`.

## 6. Fix C — SI-07 budget refund on client abort

**`DailyBudget`** gains a public `arefund(*, subject, subject_limit, consumed_day)` mirroring the internal over-cap release (budget.py:80,92–93):

```python
async def arefund(self, *, subject=None, consumed_day=None) -> None:
    if self._redis is None:
        with self._lock:            # in-process fallback path
            self._remaining = min(self._remaining + 1, self._limit)
        return
    # decr the SAME day key(s) that were consumed. `consumed_day` is captured at
    # consume time and threaded through so a refund that lands across the UTC
    # midnight rollover can't mis-decrement the wrong day's key.
    day = consumed_day or self._utc_day(self._clock())
    await self._redis.decr(NAMESPACE_BUDGET, f"narrative:{day}")
    if subject is not None:
        await self._redis.decr(NAMESPACE_BUDGET, f"narrative:{subject}:{day}")
```

The consumed UTC-day is captured on `NarrativeStreamMeta` at consume time (a new `consumed_day: str | None` field set in `stream_narrative` right after a successful `atry_consume`), so the router's abort handler passes `meta.consumed_day` into `refund`. Refund needs the subject and the day only — not the per-subject limit.

**`routers/narrative.py`** wraps the streaming loop in `try/except GeneratorExit` (a client abort raises `GeneratorExit` at the paused `yield`):

```python
try:
    async for chunk in service.stream_narrative(typed_mode, report, meta=meta, subject=subject, subject_limit=subject_limit):
        ...
    # persist branch unchanged
except GeneratorExit:
    # client aborted mid-stream: refund the slot IFF a real slot was consumed
    if not meta.cache_hit and meta.fallback_reason != "budget":
        await service.refund(subject=subject, consumed_day=meta.consumed_day)
    raise
```

Refund **only** when a slot was truly consumed: skip `meta.cache_hit` (no consume) and the budget-fallback branch (`atry_consume` returned `allowed=False`, nothing consumed). `NarrativeService.refund(...)` delegates to `DailyBudget.arefund`. `meta` already carries `cache_hit` / `fallback_reason` (service.py:33) and gains `consumed_day`. Emit `narrative.budget.refunded_on_abort`.

## 7. Fix D — SI-08 OG/card ingest attribution

**`fetchReportForUser`** (og-card-data.ts) reads the incoming request headers and forwards the same two the main proxy sends, so proxied OG/card ingests are attributed to the real visitor IP and subject to the anon `/analyze` limiter instead of the Vercel-egress bucket:

```ts
import { headers } from "next/headers";

export async function fetchReportForUser(username: string): Promise<Report | null> {
  const h = await headers();
  const clientIp = (h.get("x-forwarded-for")?.split(",")[0] ?? h.get("x-real-ip") ?? "").trim();
  const fwd: Record<string, string> = {};
  const secret = process.env.INTERNAL_PROXY_SECRET;   // server-only
  if (secret) fwd["x-internal-secret"] = secret;
  if (clientIp) fwd["x-client-ip"] = clientIp;
  const r = await fetch(`${backendBase()}/analyze/${encodeURIComponent(username)}`, {
    cache: "no-store",
    headers: fwd,
  });
  ...
}
```

The three routes stay dynamic (they already read `params`); `headers()` is legal there. No `"use cache"` wrapper — it's incompatible with reading `headers()`, and dedup is already provided by the backend's 6h report cache (warm repeats) and the 300s OG `s-maxage` (repeat renders of the same username). Note (documented, not fixed here): the attribution is only enforced when `INTERNAL_PROXY_SECRET` is set — the durable store-gating is the deferred v1.0.6 half.

## 8. Fix E — SI-09 lock TTL + holder-checked delete

- **`RedisCache`** gains `delete_if_equals(namespace, key, expected) -> bool` — `GET`; if the value equals `expected`, `DELETE`. A tiny GET→DELETE race is acceptable (fail-open convention); it prevents the cross-holder delete an unconditional `DELETE` allows.
- **`singleflight`** (locks.py) replaces both `cache.delete(...)` releases (locks.py:67,80) with `cache.delete_if_equals(NAMESPACE_LOCK, lock_key, holder_id)` — so a worker only ever deletes the lock it still owns.
- **`TTL_LOCK_SECONDS`** 30 → **60** (keys.py:36) — comfortably above the new 45s ingest deadline (the lock is held for at most one deadline-bounded ingest), so the lock no longer self-expires mid-ingest. A hard-crashed holder's lock still clears via the 60s TTL, and waiters fall through after `max_wait_seconds=25`.

## 10. Testing

**Backend (`pytest`):**
- `tests/github/test_client.py` — cap: a client with `max_calls=3` raises `GitHubCallCapExceeded` on the 4th **live** call; cache hits don't count toward the cap; `_retry_after_seconds` caps at the ceiling, parses an HTTP-date, defaults on garbage, and a `429` triggers the retry branch.
- `tests/test_dependencies.py` (or `test_analyze_e2e.py`) — `GitHubCallCapExceeded` → 503 `analysis_too_large`; ingest exceeding the deadline → 503 `analysis_timeout` (monkeypatch a slow ingest + a tiny `analyze_ingest_deadline_seconds`).
- `tests/narrative/test_budget*.py` — `arefund` decrements global + subject for the consumed day; in-process fallback refund re-increments; `arefund` after a consume nets zero.
- `tests/narrative/test_api.py` (or a router test) — a simulated `GeneratorExit` mid-stream calls refund exactly once, and only when a slot was consumed (not on cache-hit / budget-fallback).
- `tests/cache/test_locks.py` — `delete_if_equals` deletes only on match; a second holder's lock survives the first holder's release; `TTL_LOCK_SECONDS == 60`.
- `tests/cache/test_client.py` — `delete_if_equals` match / mismatch / missing-key.

**Frontend (`vitest`):**
- `og-card-data` — `fetchReportForUser` forwards `x-client-ip` (from `x-forwarded-for`) + `x-internal-secret` when the env secret is set, and omits them cleanly when unset (mock `next/headers` + `fetch`).

## 14. Exit criteria

- [ ] A client past `gh_max_calls_per_analysis` live calls raises `GitHubCallCapExceeded`; cache hits don't count; the route returns 503 `analysis_too_large`.
- [ ] `Retry-After` sleep is capped at the ceiling; an HTTP-date value parses instead of crashing; a `429` is handled like a rate-limited `403`.
- [ ] An ingest exceeding `analyze_ingest_deadline_seconds` returns 503 `analysis_timeout` and releases the worker/DB connection.
- [ ] A mid-stream client abort refunds exactly one budget slot (global + subject) — and does **not** refund on cache-hit or budget-fallback.
- [ ] `singleflight` deletes only the lock it owns (holder-checked); `TTL_LOCK_SECONDS == 60`; a second holder's lock survives the first's release.
- [ ] OG/card `fetchReportForUser` forwards `x-client-ip` + `x-internal-secret` (when set), so OG/card ingests are attributed to the visitor IP.
- [ ] Backend `ruff` clean, `pytest -q` non-DB suite green with new tests. Frontend `lint` + `tsc` + `test:run` + `build` clean.
- [ ] `CHANGELOG` + `PLAN.md` + `PROGRESS_LOG` updated; version bumped to `1.0.5`. **Not tagged/released** — paused for operator sign-off.
