# v0.3.0 — Identity Signals (design)

> Status: design approved 2026-05-16 (Shaan + Claude Opus 4.7).
> Implementation plan to be generated next via `superpowers:writing-plans`.

---

## Goal

Turn the score report from a single number into a **fingerprint**: a clear tier on a fixed ladder, a position-bar showing where the user sits and how far to the next tier, an intra-tier sub-rank (1–100), and stackable signal-driven badges. Higher tiers unlock progressively deeper signal detection, so an elite report says more than a beginner's, without changing the 100-point ceiling.

This slice is **deterministic only** — no AI. Narrative formatting moves to v0.4.0.

## Why now

Three motivations, all consistent with the product vision:

1. **Identity over score.** A bare number lacks personality. A tier + sub-rank + badges gives every report a distinct shape that's shareable on its own merits — directly feeds v0.6.0 GitHub Receipts™.
2. **Visible progression.** The position bar makes "X points to the next tier" concrete and motivates a re-analyze cycle once we have caching/persistence (v0.4.0 / v0.7.0).
3. **Closes the v0.1.0 signal-depth gap.** v0.2.0 fixed the file-existence detection; this slice adds the next layer (license, CI contents, README quality, review depth) — but gated so we never burn API budget on profiles that won't benefit.

New modules: `scoring/tiers.py`, `scoring/badges.py`, `scoring/depth.py`. Existing scorers untouched in structure; some scorers (repo_quality, engineering_maturity, oss_collab) gain optional tier-gated branches.

## §1 — Tier ladder (single-axis, total-based)

The old multi-axis category model is replaced. Tiers are computed strictly from `total`:

| Tier                   | Band (inclusive lower, exclusive upper) |
|------------------------|------------------------------------------|
| Hobbyist               | `[0, 20)`                                |
| Student Builder        | `[20, 35)`                               |
| Entry-Level Engineer   | `[35, 50)`                               |
| Professional Developer | `[50, 65)`                               |
| Senior Engineer        | `[65, 80)`                               |
| Staff Engineer         | `[80, 90)`                               |
| Principal Engineer     | `[90, 100]`                              |

Principal is the only band that includes its upper bound. So `total = 35` → Entry-Level (not Student Builder); `total = 100` → Principal.

`OSS Contributor` and `Indie Hacker` no longer exist as categories — they move to the badge catalog (§3).

**Intra-tier sub-rank** (1–100) is pure math, no extra calls:

```
sub_rank = round( (total - lower) / (upper - lower) * 100 )
```

with `upper - lower` clamped to avoid div-by-zero on Principal at 100.

Rendered: `Senior Engineer · 47/100` (47% through the Senior band).

## §2 — Position bar UX

Minimal-marker style on the results page, above the score circle:

```
Senior Engineer · 47/100
┌────────────────────────────────────────────┐
│   │    │   │    │     ●    │   │           │
└────────────────────────────────────────────┘
  H  Stu  E  Pro  Sen Staff Prin
              you are here ↑ 72/100
                8 pts to Staff
```

Spec:

- Full-width container, h-2 (8px) bar, rounded ends.
- Six tier dividers (lines) at the band boundaries.
- One filled marker (●) at `total / 100` of the bar width.
- Tier abbreviations below; current tier label rendered in foreground colour, others muted.
- Two captions below the bar:
  - Above: `<tier-name> · <sub_rank>/100`
  - Below: `<delta> pts to <next-tier>` (or `Top tier · no further band` for Principal at 100).
- Animated entry: marker slides from 0 to its final position over 1.2s with the same `easeOut` curve used by the existing aggregate-score circle, so the motion language stays consistent.
- Accessibility: `role="progressbar"`, `aria-valuemin=0`, `aria-valuemax=100`, `aria-valuenow={total}`, `aria-label={tier} · {sub_rank}/100`. Tier names are visible text, not just aria.

Component lives at `frontend/src/components/position-bar.tsx`. Imported into `results-view.tsx` between the header and the existing two-card hero.

## §3 — Badge catalog (v1)

All badges are deterministic. Each badge has a fixed trigger and one human-readable evidence line. Badges stack — a profile can earn multiple.

| Badge            | Trigger                                                                 | Evidence template                                  |
|------------------|-------------------------------------------------------------------------|----------------------------------------------------|
| OSS Contributor  | `external_prs_merged ≥ 10`                                              | "Merged {n} external PRs across {k} orgs"          |
| PR Master        | `external_prs_merged ≥ 50`                                              | "{n} external PRs merged (top-decile volume)"      |
| Maintainer       | `external_reviews ≥ 25`                                                 | "Reviewed {n} external PRs"                        |
| Star Magnet      | any non-fork repo `stars ≥ 1000`                                        | "{repo} has {stars} stars"                         |
| Polyglot         | ≥ 4 languages each ≥ 5% of total bytes                                  | "Significant in {n} languages: {list}"             |
| Long-haul        | account age ≥ 8 years AND at least one commit in last 365 days          | "Active for {years} years, still committing"       |
| Indie Hacker     | `consistency.points ≥ 8` AND `blog` set AND `hireable=True` is FALSE AND `company` not set | "Consistent solo shipper with a public portfolio"  |
| Toolmaker       | ≥ 2 non-fork repos with `stars ≥ 200` each                              | "{n} repos with ≥200 stars: {list}"                |

PR Master is a strict superset of OSS Contributor — both fire together when earned. We do not collapse them; the second one is the personality flag.

Frontend display: small pill row below the tier line, max-width matches the position bar, wraps responsively on mobile. Each pill has an icon (lucide) + name + tooltip (evidence string on hover/tap).

## §4 — Backend model changes

### New Pydantic models

```python
class Badge(BaseModel):
    slug: str                # "pr-master"
    name: str                # "PR Master"
    evidence: str            # human-readable trigger explanation

class TierInfo(BaseModel):
    name: TierName           # Literal of 7 tiers
    sub_rank: int            # 1..100 inside band
    band: tuple[int, int]    # (lower, upper_exclusive_or_100)
    next_tier: TierName | None      # None when Principal
    pts_to_next: int | None         # None when Principal
    prev_tier: TierName | None      # None when Hobbyist
    pts_above_prev: int              # 0 when Hobbyist
```

### `Report` model gains

```python
class Report(BaseModel):
    username: str
    tier: TierInfo               # NEW (replaces `category: DeveloperCategory`)
    badges: list[Badge]          # NEW
    breakdown: ScoreBreakdown
    total: int = Field(ge=0, le=100)
    generated_at: datetime
```

### Removed

- `DeveloperCategory` literal type. Replaced with `TierName = Literal[…7 tiers…]`.
- `Report.category` field. Replaced with `Report.tier: TierInfo`.

### Migration

No live persistence yet (v0.4.0 introduces Postgres). Frontend types update in lockstep. The e2e test asserts the new shape.

## §5 — Tier-gated depth signals (aggressive)

Deeper signals fire conditionally on the **base total** computed from the always-on file-existence layer. We compute the base total first, decide the tier, then add tier-appropriate enrichment passes and re-score. Total ceiling stays 100 — extra signals replace some of the same point pool, they don't expand it.

Concretely:

### Always (every tier) — already shipped in v0.2.0
- README presence per repo
- tests/specs dir presence
- `.github` / CI marker presence
- Dockerfile / vercel.json / etc. presence

"Top N" everywhere in this section means the first N non-fork repos in `profile.repos` ordering, which is GitHub's `?sort=updated` (most-recently-pushed first) — the same ordering already used by language aggregation and root-contents enrichment in v0.2.0. No re-sorting per signal.

### Professional+ (base_total ≥ 50)
- **License type per repo.** Hit `/repos/{o}/{r}/license` for the top 10 non-fork repos. A license counts when the response is `200` and `license.spdx_id` is set to anything other than `"NOASSERTION"` (so "no license file" and "explicitly no license" both count as missing). Each detected license fills the deferred 4-pt `repo_quality.license_present` signal — fires once at the scorer level when at least 50% of the top 10 have a recognised SPDX licence. One extra call per repo, up to 10.
- **CI workflow file names.** Hit `/repos/{o}/{r}/contents/.github/workflows` for the top 10 non-fork repos where `has_ci=True`. Counts of workflow files contribute to `engineering_maturity.ci_culture` evidence richness — does not change point ceiling, but evidence string becomes specific (`"3 GitHub Actions workflows"` instead of generic "Configures CI").
- **README content quality.** For the top 5 most-starred non-fork repos: fetch README, compute length and section count. Adds a `repo_quality.readme_depth` evidence row (no point change) describing the average README depth.

### Senior+ (base_total ≥ 65)
- **PR review depth.** GraphQL: pull avg `comments.totalCount` across the last 25 review contributions. Feeds a new evidence row on `oss_collab` ("Reviews average X comments/PR"). No point change at v0.3.0 — just richer evidence.
- **Dependency hygiene.** For the top 5 most-starred non-fork repos: detect presence of `package.json`, `pyproject.toml`, `Cargo.toml`, `go.mod`, `requirements.txt` etc. Multi-ecosystem use adds to `engineering_maturity.language_diversity` evidence (not points).

### Staff+ (base_total ≥ 80)
- **Commit message quality.** Sample 100 most-recent commits across top 5 repos: compute % with messages ≥ 50 chars and starting with a conventional-commit verb. Feeds a new `engineering_maturity.commit_quality` evidence row.
- **Cross-repo refactor signal.** Count GraphQL `commitContributionsByRepository` distinct repos with > 10 commits in the last year. Feeds `consistency` evidence (more granular than the existing "high_volume" check).

### Cost budget

| Base tier        | New calls beyond v0.2.0 | Total expected calls |
|------------------|--------------------------|----------------------|
| Hobbyist–Entry   | 0                        | ~25                  |
| Professional     | ~25 (10 license + 10 workflows + 5 README)   | ~50  |
| Senior           | +10 GraphQL + 5 contents | ~65                  |
| Staff+           | +1 commits + 1 GraphQL   | ~75                  |

All new calls run in parallel via `asyncio.gather` after the base score is in hand. Per-call timeout matches existing `httpx.AsyncClient` timeout (20s). Failures of any single enrichment call are silent — base scoring already gave a valid result.

### Re-scoring semantics

After enrichment, scorers re-run on the enriched `Profile`. Only points unlock that were defined in the always-on layer at the same scorer ceiling — so the maximum is still 100. Concrete deltas this slice adds to the existing ceilings:

| Scorer                | Before | New unlocked          | Net ceiling |
|-----------------------|--------|------------------------|-------------|
| `repo_quality`        | 26/30  | +4 license             | 30/30       |
| `engineering_maturity`| 20/20  | (richer evidence only) | 20/20       |
| `oss_collab`          | 15/15  | (richer evidence only) | 15/15       |
| `consistency`         | 10/10  | (richer evidence only) | 10/10       |
| `recruiter_signal`    | 15/15  | unchanged              | 15/15       |
| `learning_trajectory` | 10/10  | unchanged              | 10/10       |
| **Total**             | **96/100** | +4 license          | **100/100** |

So this slice also closes the documented 4-pt `repo_quality.license` gap.

## §9 — Open questions / future work

- **Tier names.** "Principal Engineer" vs just "Principal"? Spec uses "Principal Engineer" for consistency with Staff/Senior; reconsider when share-card design lands in v0.6.0 where shorter labels may render better.
- **Badge icons.** lucide-react has most of what we need; this slice picks pragmatic mappings. A bespoke icon set is a v0.6.0+ task.
- **Per-tier "highlight signal."** Could compute a per-tier dominant evidence row ("Your engineering maturity is what got you to Senior") for v0.5.0 narrative emphasis.
- **Re-analysis cost on cold reads.** Once caching lands in v0.7.0, the cost budget table above is an upper bound; warm cache reuses depth signals across requests.
- **Public leaderboard / percentile rank** is explicitly out of scope. Sub-rank is intra-tier-band, not population-percentile.
- **Indie Hacker trigger refinement.** Current rule excludes anyone with `hireable=True` OR a `company` value. Edge case: a self-employed founder who lists their own LLC as `company` would be excluded. We accept that trade-off in v1 — having a company field set is a strong signal you're not in indie-hacker mode. Revisit if we see real-user false negatives.
