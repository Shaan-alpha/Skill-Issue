# v1.0.6 — Shared-token quota breaker — Design

> **Status:** draft 2026-07-25, awaiting user review before `writing-plans`.
> **Slice family:** v1.0.x post-launch hardening.
> **Origin:** the deferred **extension** half of audit finding SI-03 (Workstream C), split from v1.0.5.
> **Scope decision (user, 2026-07-25):** ship **only** the shared-token quota breaker. The other two deferred extensions are **not** in this slice: SSE stream coalescing is **dropped** (marginal value — the v1.0.5 abort-refund already closed the real abuse — versus high SSE-streaming complexity/risk); OG store-gating is **skipped** (already contained by v1.0.5's OG attribution; a product-behavior change, revisit only if desired).

## 1. Goal

The v1.0.5 per-analysis call cap bounds a *single* analysis (~98 legit / 150 hard cap), but the shared anonymous GitHub token (`settings.github_token`, ~5000 requests/hour) is consumed by *all* concurrent anonymous analyses. Roughly 30–50 concurrent distinct-username cold analyses can still drain it, after which **every** anonymous analysis fails (502 / GitHub 403) until the hourly reset. Signed-in users bring their own token and are unaffected.

This slice adds a **circuit breaker**: observe the shared token's remaining quota from GitHub's `X-RateLimit-Remaining` response header, and **shed new anonymous analyses (503) before the token is fully exhausted**, preserving a reserve so the platform degrades gracefully instead of hard-failing.

## 2. Scope

**In scope:** the shared-token quota breaker (observe + shed + `is_shared_token` plumbing + one setting).

**Explicitly out (per the scope decision):**
- SSE narrative stream coalescing (dropped).
- OG/card store-gating (skipped — already contained by v1.0.5 attribution).

## 3. Grounding (from the 2026-07-24 ingest-surface map)

- `X-RateLimit-Remaining` is present on every **live** `httpx.Response` inside `GitHubClient._request` (after `resp = await self._client.request(...)`, client.py:134) but is never read. `_CachedResponse.headers = {}` (client.py:35) — the cached path carries no quota header, and cached responses `return` before the live block, so the breaker naturally only observes live calls.
- The quota is **global** across concurrent analyses, but a `GitHubClient` is built **per analysis** (dependencies.py:149). So the breaker cannot live in instance state — the observed remaining must be persisted to the shared Redis store (`self._cache`).
- `GitHubClient` is never told whether its token is the shared anon token vs. a signed-in user's token — that discriminator (`is_shared_token`) is the one missing input, derivable at dependencies.py:142–144 (`access_token == settings.github_token`).
- Redis scaffolding exists: `NAMESPACE_GH`, `RedisCache.get_json`/`set_json` (fail-open). When Redis is absent, the breaker is a no-op (can't track shared state) — consistent with the project-wide fail-open convention; the per-analysis cap still applies.

## 4. Design

### 4.1 Observe (write the low-water mark) — `github/client.py`

`GitHubClient` gains `is_shared_token: bool = False`. After the retry loop in `_request` (right after `assert resp is not None`, client.py:143), record the remaining quota — but **only when it is getting low**, so normal high-quota traffic adds zero Redis writes:

```python
# v1.0.6: record the shared token's remaining quota when it dips low, so the
# breaker can shed new anon analyses before exhaustion. Only writes below the
# watch threshold — high-quota traffic is free.
if self._is_shared_token and self._cache is not None:
    remaining = resp.headers.get("X-RateLimit-Remaining")
    if remaining is not None:
        try:
            rem = int(remaining)
        except ValueError:
            rem = None
        if rem is not None and rem < _SHARED_QUOTA_WATCH:
            await record_shared_quota(self._cache, rem)
```

- `_SHARED_QUOTA_WATCH = 1000` (module constant) — begin tracking once remaining drops below this. Above it, the Redis key stays absent and the breaker is inert.
- `record_shared_quota(cache, remaining)` — module helper: `set_json(NAMESPACE_GH, GH_SHARED_QUOTA_KEY, {"remaining": remaining}, ttl_seconds=TTL_SHARED_QUOTA)` (best-effort; swallow errors). `TTL_SHARED_QUOTA = 3700` (just over GitHub's 1-hour window) so a stale low value self-clears after the token resets, avoiding over-shedding into the next window.
- `GH_SHARED_QUOTA_KEY` added to `cache/keys.py` (a fixed key under `NAMESPACE_GH`, distinct from the request-hash keys).

### 4.2 Shed (fail-closed for anon when the reserve is gone) — `dependencies.py`

A module helper reads the low-water mark:

```python
async def shared_token_quota_ok(cache: RedisCache | None, *, min_remaining: int) -> bool:
    """True when it's safe to start a new shared-token analysis. Fail-open when
    the cache is unavailable or no low-water mark has been recorded (quota high)."""
    if cache is None:
        return True
    data = await cache.get_json(NAMESPACE_GH, GH_SHARED_QUOTA_KEY)
    if not data:
        return True
    return int(data.get("remaining", min_remaining)) >= min_remaining
```

In `_live_ingest`, after resolving `access_token`, compute the discriminator and shed **before** opening the client (so a shed costs zero GitHub calls):

```python
    is_shared = bool(settings.github_token) and access_token == settings.github_token
    if is_shared and not await shared_token_quota_ok(
        cache, min_remaining=settings.gh_shared_token_min_remaining
    ):
        logger.warning("analyze.shared_token_breaker")
        raise HTTPException(status_code=503, detail={"error": "service_busy"})

    async with GitHubClient(
        token=access_token,
        cache=cache,
        max_calls=settings.gh_max_calls_per_analysis,
        is_shared_token=is_shared,
    ) as gh:
        ...
```

- Signed-in users (own token → `is_shared` False) always bypass the breaker.
- An **in-flight** analysis is never interrupted (it already has the per-analysis cap); the breaker only sheds **new** anon analyses. This is a best-effort safety valve, not a hard reservation — combined with the per-analysis cap it substantially cuts the exhaustion risk.
- The 503 `service_busy` maps on the frontend to the existing rate-limited / try-again view (same shape as the 429 path — the frontend already renders an on-voice "busy" state for `/analyze` 5xx; confirm during implementation and reuse it, no new UI unless missing).

### 4.3 Setting

| Setting | Env var | Default |
| --- | --- | --- |
| `gh_shared_token_min_remaining` | `GH_SHARED_TOKEN_MIN_REMAINING` | 500 |

Shed new anon analyses when the observed shared-token remaining drops below this (a reserve so signed-out and signed-in traffic can still complete). `_SHARED_QUOTA_WATCH` (1000) and `TTL_SHARED_QUOTA` (3700s) are code constants.

## 5. Testing

**Backend (`pytest`):**
- `tests/github/test_client.py` — a shared-token client that receives `X-RateLimit-Remaining: 300` (< watch) writes `{"remaining": 300}` to the quota key; one at `4999` (≥ watch) writes nothing; a non-shared client never writes; a missing header is a no-op.
- `tests/test_dependencies.py` — `shared_token_quota_ok`: cache None → True; key absent → True; stored `remaining` below/at/above `min_remaining` → False/True/True. And `_live_ingest` for the shared token with a below-threshold quota key → 503 `service_busy` (no GitHub call made); a signed-in token with the same low key → bypasses (no shed).
- `tests/cache/` or `tests/github/` — `record_shared_quota` round-trips via `fake_cache`.

**Frontend:** none (503 reuses the existing `/analyze` error/busy handling; add a vitest only if a new mapping is required).

## 9. Exit criteria

- [ ] A shared-token client observing `X-RateLimit-Remaining` below the watch threshold records it to the quota key; above the threshold it writes nothing; a non-shared client never writes.
- [ ] `shared_token_quota_ok` fails open (True) when the cache is None or no low-water mark exists; returns False only when the stored remaining is below `gh_shared_token_min_remaining`.
- [ ] A new **anonymous** analysis with the quota below the floor returns 503 `service_busy` with **zero** GitHub calls; a **signed-in** analysis with the same quota state proceeds.
- [ ] Cache unavailable → breaker is a no-op (fail-open); the per-analysis cap still applies.
- [ ] Backend `ruff` clean, `pytest -q` non-DB suite green with new tests. Frontend gate unaffected (no FE change) and still green.
- [ ] `CHANGELOG` + `PLAN.md` + `PROGRESS_LOG` updated; version bumped to `1.0.6`. **Not tagged/released** — paused for operator sign-off.
