# v1.0.8 — Auth & endpoint hardening — Design

> **Status:** draft 2026-07-26, awaiting user review before `writing-plans`.
> **Slice family:** v1.0.x post-launch hardening.
> **Origin:** the heavier deferred tail of the 2026-07-24 audit (Workstream: authz/session/frontend). Prompted by "do it" on the remaining backlog.

## 1. Goal

Close the four deferred audit items that are high-value and cleanly doable, without a DB migration or a change that needs live prod verification:

1. **SI-21** — session ids are stored **hashed** at rest, so a DB-*read* compromise can't impersonate a user.
2. **SI-16** — state-changing mutations validate the request `Origin`, closing the same-site sibling-subdomain CSRF gap SameSite=Lax leaves open.
3. **SI-31 (partial)** — the CSP `connect-src` includes the backend origin, so the report-only policy is *promotable* to enforcing later.
4. **SI-37 (partial)** — a `security.txt` disclosure channel + a PR-time `dependency-review` gate.

## 2. Scope

**In scope:** SI-21, SI-16, SI-31 (connect-src only), SI-37 (security.txt + dependency-review).

**Explicitly deferred (with rationale — recorded in PLAN.md):**
- **SI-15** (`/health` split) — the version is already public (GitHub Releases, UI footer, OG cards), and reporting db/cache health *is* the endpoint's purpose; splitting it risks breaking uptime monitors for negligible gain.
- **SI-30** (GH cache-key scope namespacing) — latent only (every cached endpoint returns public data today); the "fix" reduces the shared-cache hit rate that stretches the 5000/hr GitHub budget. Revisit if a token-sensitive endpoint is ever added.
- **CSP enforcing flip** (SI-31 full) — requires nonce-based inline scripts + prod verification against real hydration/PostHog/Sentry; do it as its own slice once connect-src is in place.
- **SBOM** (SI-37 rest) — CycloneDX generation is a separate CI concern.
- **`npm audit` gate restore to `high`** — still blocked: latest Next.js is 16.2.12, inside the vulnerable range (fix is `>16.3.0-preview.7`, unreleased).

## 3. Design

### SI-21 — hash session ids at rest (`app/auth/sessions.py`)

The session cookie value is currently stored verbatim as the `Session.id` primary key, so a DB read yields working cookies. Store a **hash** instead; the raw id lives only in the cookie. **No migration** — the `id` column stays `Text`; existing raw-id rows simply stop matching the hashed lookup and are treated as invalid (clean re-login, consistent with v1.0.4 SI-22) and reaped by the expiry cron.

```python
def _hash_session_id(sid: str) -> str:
    return hashlib.sha256(sid.encode("utf-8")).hexdigest()
```

- `create_session`: `sid = _new_session_id(); db.add(Session(id=_hash_session_id(sid), ...)); return sid` — returns the RAW sid (the cookie), stores its hash.
- `get_session_with_token(session_id)`, `touch_session(session_id)`, `delete_session(session_id)`: hash the incoming cookie value before the `where(Session.id == ...)` lookup.
- No caller change — `auth.py` still sets the cookie to the returned raw sid and passes the cookie back on every request; the hashing is internal to `sessions.py`.

### SI-16 — Origin check on state-changing mutations (`app/auth/dependencies.py` + routers)

SameSite=Lax blocks cross-*site* subrequests but treats a sibling subdomain as same-site, so a credentialed `DELETE`/`POST` from `evil.skillissue.tech` (XSS / subdomain takeover) would carry the cookie. Add a dependency that validates the `Origin` header against the configured frontend origins:

```python
def require_trusted_origin(request: Request) -> None:
    origin = request.headers.get("origin")
    if origin is None:
        return  # non-browser / server-to-server callers don't send Origin
    if _origin_allowed(origin):
        return
    raise HTTPException(status_code=403, detail={"error": "bad_origin"})
```

- `_origin_allowed(origin)` matches the comma-split `settings.cors_allow_origins` **and** `settings.cors_allow_origin_regex` (via `re.fullmatch`), so real preview deploys pass.
- Absent `Origin` is allowed (browsers always send it on cross-origin fetch/XHR and on same-origin non-GET; curl/server clients that omit it are not the CSRF threat). This is defense-in-depth layered on the existing SameSite + ownership checks, not the sole gate.
- Applied as a dependency on the mutating handlers: `POST /analyses/{id}/share`, `DELETE /analyses/{id}/share`, `DELETE /analyses/{id}`, and `POST /me/refresh/{username}`.

### SI-31 (partial) — CSP connect-src includes the backend origin (`frontend/next.config.ts`)

The report-only CSP's `connect-src` omits `NEXT_PUBLIC_BACKEND_URL`, so it can never be promoted (the app's own `/me`, SSE, save/share calls would violate it). Add the backend origin (read from `process.env.NEXT_PUBLIC_BACKEND_URL` at config-eval time; Vercel sets it at build) to `connect-src`. Stays **Report-Only** — this just makes the policy correct/promotable; the enforcing flip (nonces) is a later slice.

### SI-37 (partial) — disclosure channel + PR dependency gate

- **`frontend/public/.well-known/security.txt`** — RFC 9116: `Contact`, `Expires`, `Preferred-Languages`, `Canonical`. Served at `https://skillissue.tech/.well-known/security.txt` by Next's static `public/` convention.
- **`.github/workflows/ci.yml`** — add a `dependency-review` job (`actions/dependency-review-action`) that runs **only on `pull_request`** (the action requires the PR diff), failing on newly-introduced high+ vulnerable/malicious deps. Complements the existing `pip-audit` / `npm audit` (which scan the whole tree, not the PR delta).

## 4. Testing

**Backend (`pytest`):**
- `tests/auth/test_sessions.py` (DB-fixture) — after `create_session`, the stored `Session.id` is NOT the returned sid (it's the sha256 hex); `get_session_with_token(raw_sid)` resolves the row; a wrong sid → None; `delete_session(raw_sid)` removes it. (Existing session tests keep passing since the API is unchanged.)
- `tests/auth/test_dependencies.py` (or a new `test_origin.py`) — `require_trusted_origin`: absent Origin → allowed; an allowed origin → allowed; a foreign origin → 403; a regex-matched preview origin → allowed.
- Router-level: a mutation with a foreign `Origin` → 403 (using the existing router test harness for `/analyses`).

**Frontend:** no test needed for the CSP string or security.txt (static). A `next.config` change is covered by the build.
