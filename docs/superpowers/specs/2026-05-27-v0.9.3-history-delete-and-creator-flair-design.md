# v0.9.3 — Deletable history + back-nav fix + creator flair — Design

> **Status:** approved 2026-05-27, ready for `writing-plans`.
> **Slice family:** v0.9.x. A UX/polish grab-bag of three independent changes shipped together.

## 1. Goal

Three user-requested changes:
1. Let a signed-in user **delete** a saved analysis from `/me`, with an **undo** window.
2. Fix the **stuck loading spinner** on the landing search bar after browser back-navigation.
3. Give the project's **creator account** a **golden "creator" treatment** on the results page and the shareable card — a generic distinction for whoever built the project (a single configurable `CREATOR_LOGIN`), not framed as a personal perk for any individual.

## 2. Versioning

Ships as **v0.9.3**. The previously-deferred slices shift down by one: DB pool tune → **v0.9.4**, `/security-review` + load test → **v0.9.5**, legal docs → **v0.9.6**. v0.9.2 (rate limiting) is untouched — these changes are not bundled into it.

## 3. Part 1 — Delete an analysis (with undo toast)

### 3.1 Backend
- **New route** `DELETE /analyses/{analysis_id}` in `app/routers/analyses.py` → `204 No Content`. `require_user` + ownership, mirroring the existing `share`/`revoke_share` handlers: on a missing/not-owned row, raise `HTTPException(403, {"error": "not_owner_or_missing"})` from `AnalysisNotFound`.
- **New persistence fn** `delete_analysis(db, *, analysis_id, owner_id) -> str | None` in `app/persistence/analyses.py`:
  - Verifies the row belongs to `owner_id`; raises `AnalysisNotFound` otherwise.
  - Captures `share_slug` (if any) **before** deleting so the caller can bust the share-page cache.
  - Deletes the analysis. The `analyses` table has a self-referential `latest_run_id → analysis_runs.id` plus `analysis_runs.analysis_id → analyses.id` and `narratives.analysis_run_id → analysis_runs.id`. **Planning step must verify the `ondelete` behavior in `app/db/models.py`.** If cascade is not already wired end-to-end, the function first nulls `analyses.latest_run_id` (to break the cycle), then deletes dependent `narratives` + `analysis_runs`, then the `analyses` row — all in one transaction.
  - Returns the captured `share_slug` (or `None`).
- **Route** fires `background_tasks.add_task(revalidate_share_slug, removed_slug)` when a slug came back, so a deleted public analysis's `/share/<slug>` page invalidates immediately (same pattern as `revoke_share`).

### 3.2 Frontend
- `/me` (`app/me/page.tsx`) keeps fetching server-side, then renders a new **client** component `HistoryGrid` with `analyses` as a prop. `/me` is behind auth (redirects anonymous), so losing RSC rendering of the grid costs no SEO.
- **`HistoryGrid`** (`components/history-grid.tsx`, `"use client"`) owns:
  - The list state, seeded from props.
  - Per-card delete: each `HistoryCard` renders a small `✕` button (absolute top-right) whose handler calls `e.preventDefault()` + `e.stopPropagation()` (the card is wrapped in `<Link>`).
  - **Optimistic remove + undo:** clicking `✕` removes the card from the visible list and shows one bottom toast — *"Analysis removed · Undo"* — with a ~5s timer. **Undo** restores the card and cancels the pending delete. On timeout, fire `DELETE /analyses/{id}` (`credentials: "include"`), then `router.refresh()` to resync from the server.
  - One pending-delete + toast at a time is sufficient (deletes are one-at-a-time in practice); a second delete during an open window commits the first immediately, then opens the new one.
  - If the user navigates away before the timer fires, nothing is deleted (safe — no data loss).
- `HistoryCard` gains an `onDelete` callback prop and renders the `✕`; it stays presentational.

### 3.3 Tests
- Backend (DB-fixture-gated, like the share tests): `delete_analysis` removes the row + its runs/narratives; returns the slug for a public analysis, `None` for private; raises `AnalysisNotFound` for a non-owned id. Route: 204 on success, 403 on not-owned, share-cache webhook fired when the deleted analysis was public.
- Frontend vitest: `HistoryGrid` delete→toast→undo restores the card and fires no DELETE; delete→timeout fires `DELETE /analyses/{id}`.

## 4. Part 2 — Fix the stuck loading spinner on back-navigation (bug)

**Root cause:** `components/search-bar.tsx` `handleSearch` sets `setIsLoading(true)` then `router.push("/u/<user>")`. When the user presses the browser **Back** button, the page is restored from the **bfcache** with the component's `isLoading` still `true` and the input still populated — the submit button is stuck showing `Loader2` and the input is `disabled`. (Reproduces exactly the reported screenshot.)

**Fix:** add a `useEffect` in `SearchBar` that registers a `window` `pageshow` listener resetting `isLoading` to `false` (covers the bfcache-restore path; `event.persisted` is `true` on bfcache restores, but resetting unconditionally on `pageshow` is harmless and also covers normal show). Clean up the listener on unmount.

**Test:** vitest — render `SearchBar`, drive it into the loading state (submit a valid username with `router.push` mocked), dispatch a `pageshow` event on `window`, assert the submit button is re-enabled and shows the arrow (not the spinner).

## 5. Part 3 — Golden creator flair for the creator account

### 5.1 Creator identity
- New module `lib/creator.ts`: `export const CREATOR_LOGIN = "shaan-alpha";` and `export function isCreator(username: string): boolean` (case-insensitive compare). Single source of truth; no per-component string literals.

### 5.2 Results view (`/u/shaan-alpha`)
- `results-view.tsx`: compute `const creator = isCreator(report.username)`. When true, add a `creator-theme` class to the root wrapper.
- **`creator-theme`** (in the global stylesheet) **overrides the `--accent` CSS variable to a gold hue.** Because the score ring (`text-accent`), tier chip (`bg-accent/10 text-accent`, the `bg-accent` dot), and the "Deterministic" badge all read `--accent`, they turn gold with no per-element edits.
- Add a **gold radial glow** behind the aggregate-score panel and a CSS `@keyframes` **shimmer/glitter** on the score-ring stroke (gold gradient sweep), scoped under `creator-theme` so it never affects anyone else and adds no JS.
- Render a gold **"CREATOR · SKILL ISSUE"** `Badge` in the header next to the `ANALYSIS:` badge, only when `creator`.

### 5.3 Shareable card (`/u/[username]/card` + OG PNG)
- `og-card.tsx` gains a `creator?: boolean` prop. When true: gold palette (gold accents/score) + a "CREATOR · SKILL ISSUE" label on the card. The OG image is **satori-rendered (no CSS animation)**, so the "glitter" there is a **static gold gradient**, not animated — accepted.
- The card preview page (`app/u/[username]/card/page.tsx`) and the `opengraph-image` route(s) pass `creator={isCreator(username)}` into `og-card`.

### 5.4 Tests
- vitest: `isCreator("shaan-alpha") === true`, case-insensitive, `false` for others. `og-card` renders the "CREATOR · SKILL ISSUE" label when `creator` and omits it otherwise. Results-view test asserting the `creator-theme` class + creator badge appear for `shaan-alpha` and not for a normal user.

## 6. Out of scope
- No global toast/notification system — the undo toast is owned by `HistoryGrid`.
- No soft-delete column/migration — undo is a client-side deferred commit; the row is only deleted after the window elapses.
- No creator treatment on `/me` history tiles or the landing page (gold scope is results page + shareable card per the locked decision).
- No animated glitter in the OG PNG (satori limitation).
