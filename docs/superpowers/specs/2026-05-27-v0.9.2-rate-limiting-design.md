# v0.9.2 — Rate limiting (IP + user) — Design

> **Status:** approved 2026-05-27, ready for `writing-plans`.
> **Slice family:** v0.9.x Beta hardening.
> **Supersedes the slice number:** rate limiting takes the `v0.9.2` slot; the data-gated DB pool tune moves to `v0.9.3` (see §10).

## 1. Goal

Cap request volume on the two expensive, anonymous-accessible backend endpoints so a single client cannot burn the shared GitHub-token quota, the database, or the shared LLM daily budget. Signed-in users — who bring their own GitHub token (dedicated 5000/hr budget since v0.5.0) — get more generous, per-user caps. Anonymous users are capped per-IP.

This is the **core rate-limiting** slice only. Abuse heuristics (suspicious-username throttle, burst/enumeration detection, temp IP banlists) are explicitly deferred to a later v0.9.x patch.

## 2. Scope

**In scope:**
- `GET /analyze/{username}` — cold ingest fans out GitHub API calls; the primary GH-quota/DB cost burner.
- `GET /narrative/{username}` — SSE; draws on the shared daily LLM budget (Layer D).
- Generalizing the existing `try_increment_counter` primitive from `user_id: int` to `subject: str`.
- A trusted-proxy mechanism so anonymous `/analyze` (proxied through the Next.js RSC) is attributed to the real client IP.
- On-voice frontend handling of a 429 on the analyze path.

**Out of scope (deferred):**
- Abuse heuristics / suspicious-username regex throttle.
- `/auth` (OAuth login/callback) throttling.
- Per-day caps — hourly only, matching the existing UTC-hour bucket.
- `/me/refresh/{username}` — already carries a per-user 10/hr cap from v0.8.2; untouched.

## 3. Threat model & the IP-attribution problem

The backend is publicly reachable (the narrative `EventSource` connects to it directly from the browser via `NEXT_PUBLIC_BACKEND_URL`). The two endpoints have **opposite** IP-visibility characteristics:

| Endpoint | Call path | IP the backend sees |
| --- | --- | --- |
| `/narrative` | Browser `EventSource` → backend (direct) | Real client IP (Vercel edge `x-forwarded-for` / `x-real-ip`) ✅ |
| `/analyze` (website) | Browser → Next RSC `fetch` → backend | Vercel **infra** IP ❌ |
| `/analyze` (direct/scripted) | Client → backend (direct) | Real client IP ✅ |

Naive per-IP limiting on `/analyze` would lump **all anonymous website visitors** into one Vercel-infra-IP bucket and throttle them collectively. The scripted-abuser path (direct to backend) is attributed correctly on its own.

**Resolution — trusted-proxy header (mirrors v0.8.6's `REVALIDATE_SECRET`):** The RSC forwards the real client IP plus a shared secret. The backend trusts a forwarded `X-Client-IP` **only** when `X-Internal-Secret` matches `settings.internal_proxy_secret`; otherwise it falls back to the connection IP. This attributes every path correctly:
- Website anonymous analyze → real browser IP (via trusted `X-Client-IP`).
- Direct/scripted analyze → real connection IP (no valid secret → ignore any spoofed `X-Client-IP`).
- Signed-in analyze → limited per-user regardless of IP (the RSC forwards the `si_session` cookie).

## 4. Limit model & defaults

**Auth-tier model:** anonymous → per-IP; signed-in → per-user. Defaults (all env-overridable `Settings` fields; narrative ≈ 1.5× analyze because one analysis view can fire both Roast and Mentor):

| Setting | Env var | Default |
| --- | --- | --- |
| `analyze_anon_per_ip_per_hour` | `ANALYZE_ANON_PER_IP_PER_HOUR` | 20 |
| `analyze_user_per_hour` | `ANALYZE_USER_PER_HOUR` | 60 |
| `narrative_anon_per_ip_per_hour` | `NARRATIVE_ANON_PER_IP_PER_HOUR` | 30 |
| `narrative_user_per_hour` | `NARRATIVE_USER_PER_HOUR` | 90 |
| `internal_proxy_secret` | `INTERNAL_PROXY_SECRET` | `None` |

## 5. Components

### 5.1 Generalize the primitive (`app/cache/rate_limit.py`, `app/cache/keys.py`)
- `rate_limit_key(name, *, subject: str, hour_bucket: str)` — `user_id: int` → `subject: str`. Final composed key: `{name}:{subject}:{hour_bucket}`.
- `try_increment_counter(cache, *, name, subject: str, limit, hour_bucket, ttl_seconds=3700)` — same atomic INCR + EXPIRE-on-first-write, same **fail-open** (Redis error → `RateLimitResult(allowed=True, current=0)`).
- The single existing caller, `app/routers/refresh.py`, passes `subject=f"user:{session.user.id}"`.

### 5.2 New module `app/ratelimit.py`
- `client_ip(request, *, trusted_proxy: bool) -> str` — if `trusted_proxy` and `X-Client-IP` present, return it; else `x-real-ip`; else leftmost of `x-forwarded-for`; else `request.client.host`; else `"unknown"`.
- `is_trusted_proxy(request) -> bool` — `hmac.compare_digest(request.headers.get("X-Internal-Secret",""), settings.internal_proxy_secret)`; returns `False` when the secret is unset.
- `_hour_bucket(now)` and `_seconds_until_next_hour(now)` — **moved here** from `refresh.py`; `refresh.py` imports them back (removes duplication).
- `make_rate_limiter(name, *, anon_limit_field, user_limit_field, via_trusted_proxy: bool) -> dependency` — factory returning an async FastAPI dependency. `via_trusted_proxy` is `True` for the analyze limiter (reached through the RSC proxy) and `False` for narrative (browser-direct):
  1. `cache = get_cache()`; if `None` → return (cache unconfigured → no limiting, consistent with fail-open).
  2. Resolve `optional_session` (FastAPI caches it per-request, so no extra DB query vs. the route's own `optional_session`).
  3. **Signed-in:** `subject=f"user:{session.user.id}"`, `limit=getattr(settings, user_limit_field)`.
  4. **Anonymous:** if `via_trusted_proxy` **and** `settings.internal_proxy_secret is None` → **skip enforcement** (see §6) with a one-time warning log. Otherwise `subject=f"ip:{client_ip(request, trusted_proxy=is_trusted_proxy(request))}"`, `limit=getattr(settings, anon_limit_field)`. (For narrative, `via_trusted_proxy=False`, so `is_trusted_proxy` is `False`, no `X-Client-IP` is sent, and `client_ip` resolves the real browser IP via `x-real-ip` — enforcement is never skipped.)
  5. `result = await try_increment_counter(...)`; if `not result.allowed` → raise 429.
  - Settings read at call-time via the `app.settings` module reference (not an import-time binding) so test monkeypatching propagates (the v0.8.1 lesson).
- Two limiter instances exported: `analyze_rate_limiter` (`via_trusted_proxy=True`) and `narrative_rate_limiter` (`via_trusted_proxy=False`).

### 5.3 429 response shape
`{"detail": "rate_limited", "retry_after_seconds": N}`, HTTP 429, header `Retry-After: N`, where `N = _seconds_until_next_hour(now)` — identical to the v0.8.2 force-refresh shape.

### 5.4 Wiring
- `main.py` `analyze_user`: add `_rl: Annotated[None, Depends(analyze_rate_limiter)]`.
- `narrative.py` `get_narrative`: add `_rl: Annotated[None, Depends(narrative_rate_limiter)]`. The dependency runs before the `StreamingResponse` is constructed, so a 429 is returned as clean JSON, never a half-open event stream.

### 5.5 Frontend (`frontend/src/app/u/[username]/page.tsx`)
- `getAnalysis` reads the incoming request's client IP via `headers()` (`x-forwarded-for` leftmost / `x-real-ip`) and forwards two headers to the backend: `X-Internal-Secret: process.env.INTERNAL_PROXY_SECRET` (server-only, **never** `NEXT_PUBLIC`) and `X-Client-IP: <client ip>`. Both are added alongside the existing `cookie` forward.
- New `AnalysisResult` variant `{ kind: "rate_limited"; retryAfterSeconds: number }`. On `res.status === 429`, parse `retry_after_seconds` and return that variant instead of `throw new Error` (which currently routes to `error.tsx`'s misleading "API may be down").
- New on-voice component (e.g. `RateLimited`) rendered for that variant — same treatment as the existing `NotAnIndividual` 422 view.
- The narrative client path is unchanged: a 429 surfaces through the existing `EventSource` `onerror → onComplete` graceful path (no narrative that request; rest of the page unaffected).

## 6. Graceful degradation

- **`internal_proxy_secret` unset:** anonymous `/analyze` enforcement is **skipped** (one-time warning log). Without this, every website visitor collapses into the single Vercel-infra-IP bucket and throttles each other at 20/hr the moment we deploy. Provisioning the secret on both sides is the switch that turns anonymous-analyze protection on. Signed-in/user limits and all narrative limits remain active regardless.
- **Cache unconfigured / Redis error:** fail-open — the request is allowed. The cache is a perf/abuse-mitigation layer, never a correctness boundary (project-wide convention since v0.7.0).

## 7. Observability

- A structured log line on every throttle: `event=rate_limit.throttled` with `{endpoint, subject_type: "ip"|"user", limit}`. **No raw IP or user_id** in the log body — honors the v0.8.0 PII contract.
- `docs/OBSERVABILITY.md` gains a `rate_limit.*` taxonomy row (`throttled`, plus the `internal_proxy_secret`-unset warning).
- No Sentry capture and no PostHog event for throttles — keep it log-only, matching the v0.8.1 cron approach. Revisit if real abuse telemetry warrants alerting.

## 8. Testing

**Backend (`backend/tests/ratelimit/`):**
- `test_identity.py` — `client_ip` across trusted `X-Client-IP`, `x-real-ip`, multi-hop `x-forwarded-for`, and `request.client` fallback; `is_trusted_proxy` match / mismatch / secret-unset.
- `test_dependency.py` — anon under/at/over limit (200/200/429), signed-in uses the user limit, secret-unset skips anon analyze enforcement, cache-unconfigured and Redis-error both fail open.
- Route-level: `/analyze` and `/narrative` over-limit → 429 + `Retry-After` (using the fake-Redis fixture).
- Update `tests/cache/test_rate_limit.py` and `tests/cache/test_keys_rate_limit.py` for the `subject` rename; update the `refresh.py` caller's tests if they assert the old kwarg.

**Frontend (vitest):**
- `getAnalysis` (or its extracted helper) maps a 429 to the `rate_limited` variant; the `RateLimited` view renders the on-voice copy and a sensible retry hint.

## 9. Provisioning gate (user action — AGENTS rule 5)

`INTERNAL_PROXY_SECRET` — generate one value (`python -c "import secrets; print(secrets.token_hex(32))"`) and set the **same** value on **both** the frontend and backend services, Production + Preview, as a Sensitive env var. The four limit knobs ship with working defaults and need no action unless tuning.

## 12. Exit criteria

- [ ] `rate_limit_key` / `try_increment_counter` take `subject: str`; `refresh.py` adapted; cache tests green.
- [ ] Anonymous `/analyze` over the IP cap (secret configured) → 429 + `Retry-After`; under cap → 200.
- [ ] Signed-in `/analyze` and `/narrative` limited per-user, independent of IP.
- [ ] Anonymous `/narrative` over the IP cap → 429 (browser-direct, real IP).
- [ ] `internal_proxy_secret` unset → anonymous `/analyze` enforcement skipped (no collateral throttling); narrative + user limits still active.
- [ ] Spoofed `X-Client-IP` without a valid secret is ignored (falls back to connection IP).
- [ ] Cache unconfigured / Redis error → fail-open (request allowed).
- [ ] Frontend renders an on-voice 429 view, not `error.tsx`.
- [ ] `event=rate_limit.throttled` logged with no raw IP/user_id; documented in `OBSERVABILITY.md`.
- [ ] Backend `ruff check .` + `ruff format --check .` clean; `pytest -q` non-DB suite green with the new tests. Frontend `lint` + `tsc` + `test:run` + `build` clean.
- [ ] `CHANGELOG.md` + `docs/PROGRESS_LOG.md` + `PLAN.md` updated; version bumped to `0.9.2`.
