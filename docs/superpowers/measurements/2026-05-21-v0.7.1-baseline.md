## Notes

- **LCP element couldn't be extracted** from the Lighthouse JSON (`largest-contentful-paint-element` had no details). The 4s LCP is the killer metric — likely the aggregate-score number, which can only render after the SVG circle animation runs (the circle's `strokeDashoffset` animates in via framer-motion, delay 0.1s, duration 1.2s — so any frame before ~1.3s after mount is empty).
- **CLS at 0.080** is already in budget. Avatar `<img>` tags are the main remaining shifter — Task 5 should drop this to ~0.
- **Bundle is dominated by `@base-ui/react` at 150 KB.** Even with `optimizePackageImports` (Task 1, already wired), the savings depend on how aggressively Next 16's transform deduplicates the Menu primitives we use in `site-header.tsx`. Will measure in Task 4.
- **framer-motion at 52 KB** is `domMax` features. Switching to `domAnimation` in Task 3 should drop ~25 KB.

## Optimization expectations vs. measured gap

| Optimization | Expected wins | Closes how much of the gap? |
| --- | --- | --- |
| LazyMotion shrink (T3) | -25 KB JS, faster TTI | small TTI/LCP improvement |
| optimizePackageImports verify (T4) | should already be live; lucide-react + base-ui leaner | unknown, measure in T4 |
| Next Image avatars (T5) | CLS → ~0 | already in budget, defence-in-depth |
| ISR /share (T6) | dramatic LCP on `/share/[slug]` cold | doesn't help `/u/[username]` |

**Verdict:** the four queued optimizations are necessary but probably not sufficient to close a 1,400ms LCP gap. Task 7 will likely need at least one iteration. Strongest candidate: defer the SVG-circle animation's `initial` offset so the score number renders inside the circle on first paint, then animate the stroke in afterward.
