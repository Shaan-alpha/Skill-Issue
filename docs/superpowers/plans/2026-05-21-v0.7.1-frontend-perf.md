# v0.7.1 — Frontend Performance Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Hit the v0.7.1 perf budget on `/u/[username]` and `/share/[slug]` — Lighthouse mobile performance ≥ 95, TTI ≤ 2.5s, LCP ≤ 2.5s, CLS ≤ 0.1.

**Architecture:** This is a *measurement-first* slice, not a feature slice. We (1) capture a baseline using Lighthouse + `@next/bundle-analyzer`, (2) apply four targeted, low-risk optimizations — LazyMotion feature set, `optimizePackageImports`, Next `<Image>` for avatars, ISR for the public share route — and (3) re-measure to confirm the budget is hit. If it isn't, we iterate on the largest remaining contributor before declaring done.

**Tech Stack:** Next.js 16 App Router (Turbopack), React 19, TailwindCSS 4, framer-motion 12 (LazyMotion), lucide-react, Base UI, `@next/bundle-analyzer`, Lighthouse CLI.

**Why these four optimizations and only these four:**

| Optimization | Expected wins | Risk |
| --- | --- | --- |
| LazyMotion `domMax` → `domAnimation` | ~25KB off the framer-motion features bundle. We use animate/initial/transition but not drag/layoutId-as-physics. | Low — `m.` components keep working; only advanced features removed. |
| `optimizePackageImports` for `lucide-react` + `@base-ui/react` | Tree-shaking on barrel imports — Next 16 ships per-icon chunks. Both libraries are documented as supported. | Zero — build-time transform. |
| Next `<Image>` for avatars | Sets `width`/`height` so layout doesn't shift when the avatar loads (kills the CLS from header + share-attribution + history grid). Also serves WebP. | Low — `images.remotePatterns` must include `avatars.githubusercontent.com`. |
| ISR on `/share/[slug]` | Public, stable content. Drops TTFB from full backend round-trip to edge cache hit. Massive LCP win for cold visitors. | Low — only public slugs are revalidated on a fixed interval. Revocation is already covered by 404. |

What we **don't** touch in this slice (deferred to v0.8.0 unless re-measurement forces it):
- Replacing `framer-motion` entirely. LazyMotion is the right tool; just feed it less.
- Server Components conversion of `results-view.tsx`. The animation entry effects need client; not worth ripping out for a 95 score.
- Custom font loading strategy. Geist + Geist_Mono via `next/font/google` already ship `font-display: swap` and self-host.
- Lighthouse CI integration. Manual run twice is enough to certify the budget; CI integration belongs with the Sentry/observability work in v0.8.0.

## Task 6: ISR the public share route

**Files:**
- Modify: `frontend/src/app/share/[slug]/page.tsx`

**Why:** `/share/[slug]` is the route social-media crawlers and inbound link clicks hit cold. It is **public** and **stable** for a given slug (revocation just makes the slug 404 — never returns stale content). Today it sets `export const dynamic = "force-dynamic"`, which means every visit pays a full backend round-trip. Switching to `revalidate = 3600` lets Next cache the rendered HTML at the edge for an hour. Cold visitors see the page in well under the LCP budget.
