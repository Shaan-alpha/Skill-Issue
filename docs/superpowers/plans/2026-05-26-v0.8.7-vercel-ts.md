# v0.8.7 — `vercel.json` → `vercel.ts` Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the root `vercel.json` with a typed `vercel.ts` exporting `VercelConfig` from `@vercel/config/v1`. Same services, same cron, same branch-deploy filter — purely a config-shape migration tracking Vercel's 2026-02-27 recommended config form.

**Architecture:** One new TypeScript file at repo root (`vercel.ts`) replaces the current JSON literal. A minimal root `package.json` makes `@vercel/config` resolvable for Vercel's build pipeline and for local `tsc`. A minimal root `tsconfig.json` lets CI typecheck the lone file standalone. Backend `backend/vercel.json` is untouched (per-function static config, no logic to type).

**Tech Stack:** TypeScript 5 (devDep via `frontend/`-style pin), `@vercel/config` (new, v1.x), Vercel CLI implicitly via the platform's build step (no local CLI required).

**Spec:** [`docs/superpowers/specs/2026-05-26-v0.8.7-vercel-ts-design.md`](../specs/2026-05-26-v0.8.7-vercel-ts-design.md).

**Branch:** `feat/v0.8.7-vercel-ts` (already created, spec already committed as `4e8d94a` + optimization pass `f57da18`).

**Notable departure from TDD:** This slice has no runtime code — `vercel.ts` is data, not logic. There are no unit tests to write. The verification analog is **TSC clean + git status clean + post-merge prod smoke**. Each task ends with a typecheck (or equivalent verification) and a commit.

```ts
import type { VercelConfig } from '@vercel/config/v1';

// File-local type augmentation: @vercel/config v1.x does not currently
// type the `experimentalServices` field shown in
// https://vercel.com/docs/services. Runtime shape is documented and
// stable; this intersection lets us keep `VercelConfig` autocomplete
// for the other keys while honoring the documented services schema.
// Drop this alias once upstream types catch up.
type Config = VercelConfig & {
  experimentalServices?: Record<
    string,
    { entrypoint: string; routePrefix?: string; framework?: string }
  >;
};

export const config: Config = {
  experimentalServices: {
    frontend: {
      entrypoint: 'frontend',
      routePrefix: '/',
      framework: 'nextjs',
    },
    backend: {
      entrypoint: 'backend',
      routePrefix: '/_/backend',
    },
  },
  crons: [

      path: '/_/backend/cron/refresh-saved-analyses',
      schedule: '0 3 * * *',

      'fix/*': false,
      'chore/*': false,
      'docs/*': false,
      'ops/*': false,
      'style/*': false,
      'refactor/*': false,
      'test/*': false,
    },
  },
};
```
