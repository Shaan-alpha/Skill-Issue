# v1.0.10 Dependency-Manifest Drift Guard Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make a mismatch between `backend/pyproject.toml`, `backend/uv.lock` and `backend/requirements.txt` fail CI deterministically instead of surfacing by accident.

**Architecture:** One new CI step in the existing `backend` job, composed entirely from native tooling — no new source files and no bespoke logic. `uv lock --check` asserts `pyproject.toml → uv.lock`; regenerating `requirements.txt` in place and running `git diff --exit-code` asserts `uv.lock → requirements.txt`.

**Tech Stack:** GitHub Actions, `uv` 0.11.12, `git`.

**Spec:** [`docs/superpowers/specs/2026-07-28-v1.0.10-manifest-drift-guard-design.md`](../specs/2026-07-28-v1.0.10-manifest-drift-guard-design.md)

## Global Constraints

- **No new source files.** The whole change is one CI step plus comment and version edits. If you find yourself writing a Python module, stop — the spec explicitly rejects bespoke logic here.
- **Regenerate in place; never diff a temp file.** `uv export` writes a header echoing its own `-o` argument, so exporting to a temp path differs on line 2 by construction and reports drift on every run.
- **The drift test must be committed, not just written to the working tree.** The regenerate step overwrites an uncommitted edit before `git diff` runs, so a working-tree-only test heals the drift and passes vacuously. This trap was hit while validating the design.
- **Exact step name:** `Dependency manifests in sync`.
- **Ignore CRLF warnings on Windows.** The repo has no `.gitattributes`, so `git add` prints `LF will be replaced by CRLF` on these files. This does not affect the guard: Git normalises to LF in the index before diffing, so the comparison is LF-to-LF on both Windows and the Linux runner. Verified during design validation — the drifted-file test produced a one-line diff, not a whole-file one. If you ever *do* see a whole-file diff, that is the signal something is wrong with line-ending config, not with the manifests.
- **Placement:** in the `backend` job, immediately before `pip-audit (shipped dependency CVEs)`.
- **Paths are unqualified** (`requirements.txt`, not `backend/requirements.txt`) because the `backend` job sets `defaults.run.working-directory: backend`.
- **Version target:** `1.0.10` in all three constants — `backend/app/settings.py:6`, `frontend/package.json:3`, `frontend/src/lib/site.ts:4`. The v1.0.7 drift guard at `frontend/src/lib/site.test.ts` fails if `package.json` and `site.ts` disagree.
- **No co-authored-by trailers on any commit.**

## Considered and rejected: flipping `uv sync --frozen` to `--locked`

`.github/workflows/ci.yml:54` currently runs `uv sync --frozen --dev`. `--frozen` uses the lockfile as-is *without* checking it against `pyproject.toml`; `--locked` would error if the lock were stale, giving link one for free with no new invocation.

Rejected. The failure would surface as a dependency-install error partway up the job, which reads as "the install broke" rather than "your manifests disagree". A separately named step makes the failure self-describing in the checks UI and keeps the whole drift concern in one place a reader can find. The cost is one extra sub-second command.

Do not flip `--frozen` as well — that would make link one checked twice, and a second failure mode for the same condition.

- [ ] **Step 2: Verify both commands pass against the current, known-good tree**

This is the baseline. If it fails here, the repo already has drift and that must be fixed and committed before adding a guard for it.

```bash
cd backend
uv lock --check
uv export --no-hashes --no-dev --format requirements-txt -o requirements.txt
git diff --exit-code -- requirements.txt; echo "EXIT=$?"
```

Expected: `uv lock --check` prints a `Resolved N packages` line and exits 0; `EXIT=0`.

- [ ] **Step 3: Prove the guard catches real drift**

Real drift means the *committed* file is wrong. Commit a tampered manifest on a scratch branch, then run the guard against it.

```bash
cd ..
git checkout -b tmp/drift-check
python -c "
p='backend/requirements.txt'
s=open(p,encoding='utf-8').read()
s=s.replace('sqlalchemy==2.0.51','sqlalchemy==2.0.49')
open(p,'w',encoding='utf-8',newline='').write(s)
"
git commit -qam "test: simulate a committed transitive-pin edit"

cd backend
uv lock --check; echo "lock-check EXIT=$?"
uv export --no-hashes --no-dev --format requirements-txt -o requirements.txt
git diff --exit-code -- requirements.txt; echo "diff EXIT=$?"
```

Expected: `lock-check EXIT=0` (pyproject and uv.lock are untouched — this is the point of having two checks), and `diff EXIT=1` printing:

```
-sqlalchemy==2.0.49
+sqlalchemy==2.0.51
```

If `diff EXIT=0`, the tamper did not get committed — check `git status` and redo Step 3. Do not proceed until you have seen exit 1.

*(If `sqlalchemy==2.0.51` is no longer the pinned version by the time you run this, pick any other `name==version` line from `backend/requirements.txt` and change its version instead.)*

- [ ] **Step 5: Insert the step into `ci.yml`**

In `.github/workflows/ci.yml`, insert immediately **before** the `- name: pip-audit (shipped dependency CVEs)` step (currently line 69), separated by a blank line:

```yaml
      - name: Dependency manifests in sync
        # backend/requirements.txt is generated by `uv export`, so editing a
        # pinned line in it by hand bypasses the resolver that makes those pins
        # coherent. Dependabot #45 did exactly that -- it bumped transitive
        # pydantic-core past the version pydantic pins exactly, producing a
        # manifest that could not resolve.
        #
        # Nothing detected that as drift; it surfaced only because pip-audit
        # happened to fail on the result. A drifted manifest that still resolves
        # would pass silently, and in v0.8.5 exactly that went unnoticed for
        # months (requirements.txt was missing 9 of 15 direct dependencies).
        #
        # Regenerating in place rather than diffing a temp file is deliberate:
        # uv's header echoes its own `-o` argument, so a temp path differs on
        # line 2 every time. Same command in, byte-identical file out, and any
        # remaining difference is real drift.
        run: |
          uv lock --check
          uv export --no-hashes --no-dev --format requirements-txt -o requirements.txt
          git diff --exit-code -- requirements.txt
```

- [ ] **Step 6: Verify the job/step tree is intact**
